# GDT（全局描述符表）详解

## 为什么需要 GDT？

在 x86 保护模式下，CPU 不再直接使用段寄存器作为内存地址，而是通过 GDT 来管理内存段的访问权限和属性。GDT 是保护模式的核心数据结构。

---

## 一、GDT 的整体结构

```
GDT 在内存中的布局：

          ┌─────────────────┐
          │   空描述符       │  ← 0 号描述符（必须保留，不能使用）
          │   (8 字节)       │
          ├─────────────────┤
          │   代码段描述符   │  ← 1 号描述符
          │   (8 字节)       │
          ├─────────────────┤
          │   数据段描述符   │  ← 2 号描述符
          │   (8 字节)       │
          └─────────────────┘
          ↑
    gdt_start（GDT 起始地址）
```

---

## 二、段描述符的详细结构

每个段描述符占 **8 字节（64 位）**，结构如下：

```
 31                   16 15                    0
┌──────────────────────┬──────────────────────┐
│  Base Address(31-24) │ Flags+Limit(19-16)   │  ← 第 7-4 字节
├──────────────────────┼──────────────────────┤
│  Access Byte         │  Base Address(23-16) │  ← 第 5-4 字节
├──────────────────────┼──────────────────────┤
│  Base Address(15-0)  │  Limit (15-0)        │  ← 第 3-0 字节
└──────────────────────┴──────────────────────┘
```

### 2.1 字段详解

| 字段 | 位数 | 作用 |
|------|------|------|
| **Base Address** | 32 位 | 段的起始物理地址 |
| **Limit** | 20 位 | 段的大小限制 |
| **Access Byte** | 8 位 | 访问权限和属性 |
| **Flags** | 4 位 | 粒度、操作数大小等 |

---

## 三、我们的 GDT 代码逐行解释

### 3.1 空描述符

```nasm
gdt_start:
    dd 0x00000000       ; 低 4 字节
    dd 0x00000000       ; 高 4 字节
```

**为什么需要空描述符？**
- Intel 规定 GDT 的 0 号描述符必须为空
- 如果加载到段寄存器会触发异常，用于捕获编程错误
- 作为"未初始化"的默认值

### 3.2 代码段描述符

```nasm
gdt_code:
    dw 0xFFFF           ; Limit (15-0): 0xFFFF
    dw 0x0000           ; Base (15-0): 0x0000
    db 0x00             ; Base (23-16): 0x00
    db 10011010b        ; Access Byte
    db 11001111b        ; Flags + Limit(19-16)
    db 0x00             ; Base (31-24): 0x00
```

#### 逐字节分析：

| 字节 | 值 | 含义 |
|------|-----|------|
| 0-1 | `0xFFFF` | Limit 低 16 位 = 0xFFFF |
| 2-3 | `0x0000` | Base 低 16 位 = 0x0000 |
| 4 | `0x00` | Base 中 8 位 = 0x00 |
| 5 | `10011010b` | Access Byte（见下文） |
| 6 | `11001111b` | Flags + Limit 高 4 位 |
| 7 | `0x00` | Base 高 8 位 = 0x00 |

#### Access Byte 详解（`10011010b`）：

```
  7   6   5   4   3   2   1   0
┌───┬───┬───┬───┬───┬───┬───┬───┐
│ P │ DPL │ S │     Type      │
│ 1 │ 0 │ 0 │ 1 │ 1 │ 0 │ 1 │ 0 │
└───┴───┴───┴───┴───┴───┴───┴───┘
```

| 位 | 名称 | 值 | 含义 |
|----|------|-----|------|
| 7 | **P** (Present) | 1 | 段存在于内存中 |
| 6-5 | **DPL** (Descriptor Privilege Level) | 00 | 特权级 0（最高，内核级） |
| 4 | **S** (Descriptor Type) | 1 | 代码/数据段（0=系统段） |
| 3-0 | **Type** | 1010 | 代码段、一致、可读 |

**Type 字段详解（代码段）：**
- Bit 3: 1 = 代码段（0 = 数据段）
- Bit 2: 0 = 非一致代码段（1 = 一致）
- Bit 1: 1 = 可读（代码段可以被读取）
- Bit 0: 0 = 未被访问（CPU 会在访问时设为 1）

#### Flags 详解（`11001111b`）：

```
  7   6   5   4   3   2   1   0
┌───┬───┬───┬───┬───┬───┬───┬───┐
│ G │ D │ L │AVL│    Limit(19-16) │
│ 1 │ 1 │ 0 │ 0 │ 1 │ 1 │ 1 │ 1 │
└───┴───┴───┴───┴───┴───┴───┴───┘
```

| 位 | 名称 | 值 | 含义 |
|----|------|-----|------|
| 7 | **G** (Granularity) | 1 | 粒度 = 4KB（0 = 1字节） |
| 6 | **D/B** (Default/Big) | 1 | 32 位操作数（0 = 16位） |
| 5 | **L** (Long) | 0 | 非 64 位代码段 |
| 4 | **AVL** (Available) | 0 | 保留给系统软件使用 |
| 3-0 | **Limit(19-16)** | 1111 | 界限高 4 位 = 0xF |

**为什么界限是 0xFFFFF？**
- Limit = `0xF` << 16 + `0xFFFF` = 0xFFFFF
- G=1 表示粒度为 4KB
- 实际段大小 = 0xFFFFF * 4KB = 4GB - 4KB ≈ 4GB

### 3.3 数据段描述符

```nasm
gdt_data:
    dw 0xFFFF           ; Limit (15-0)
    dw 0x0000           ; Base (15-0)
    db 0x00             ; Base (23-16)
    db 10010010b        ; Access Byte（与代码段的区别在这里）
    db 11001111b        ; Flags + Limit(19-16)
    db 0x00             ; Base (31-24)
```

**与代码段唯一的区别：Access Byte = `10010010b`**

```
  7   6   5   4   3   2   1   0
┌───┬───┬───┬───┬───┬───┬───┬───┐
│ P │ DPL │ S │     Type      │
│ 1 │ 0 │ 0 │ 1 │ 0 │ 0 │ 1 │ 0 │
└───┴───┴───┴───┴───┴───┴───┴───┘
```

**Type 字段详解（数据段）：**
- Bit 3: 0 = 数据段
- Bit 2: 0 = 向上扩展（地址 < Base + Limit）
- Bit 1: 1 = 可写
- Bit 0: 0 = 未被访问

## 四、GDT 描述符（lgdt 指令用）

```nasm
gdt_descriptor:
    dw gdt_end - gdt_start - 1  ; GDT 界限
    dd gdt_start                ; GDT 基址
```

**为什么界限要减 1？**
- 界限表示的是最大有效偏移量
- 如果 GDT 大小是 24 字节，最大偏移是 23
- 所以界限 = 大小 - 1

**lgdt 指令执行后，GDTR 寄存器内容：**
```
GDTR:
┌─────────────────────┬──────────────────────┐
│    Limit (16位)      │     Base (32位)       │
│   (GDT大小-1)        │   (GDT起始物理地址)    │
└─────────────────────┴──────────────────────┘
```

## 五、段选择子

```nasm
CODE_SEG equ gdt_code - gdt_start  ; = 0x08
DATA_SEG equ gdt_data - gdt_start  ; = 0x10
```

### 5.1 段选择子格式

```
 15                        3  2   0
┌───────────────────────────┬───┬───┐
│      Index (13位)          │TI │RPL│
│      描述符索引             │   │   │
└───────────────────────────┴───┴───┘
```

| 字段 | 位数 | 含义 |
|------|------|------|
| **Index** | 13 位 | GDT/LDT 中的描述符索引（0-8191） |
| **TI** | 1 位 | 表指示符（0=GDT，1=LDT） |
| **RPL** | 2 位 | 请求特权级（0-3） |

### 5.2 计算过程

```
CODE_SEG = gdt_code - gdt_start
         = 第 1 个描述符的偏移
         = 8 (0x08)
         
二进制：0000 0000 0000 1000
        │              ││└┬┘
        │              ││ └─ RPL = 00 (特权级 0)
        │              │└─── TI = 0 (使用 GDT)
        │              └──── Index = 1 (1 号描述符)
        └────────────────── 高 13 位未使用

DATA_SEG = gdt_data - gdt_start
         = 第 2 个描述符的偏移
         = 16 (0x10)
```

## 六、为什么使用平坦模型（Flat Model）？

### 6.1 什么是平坦模型？

我们的 GDT 配置：
- 代码段：Base=0, Limit=4GB
- 数据段：Base=0, Limit=4GB

两个段都覆盖整个 4GB 地址空间！

### 6.2 平坦模型的优势

| 优势 | 说明 |
|------|------|
| **简化内存管理** | 不需要频繁切换段寄存器 |
| **兼容 C 语言** | C 语言假设线性地址空间 |
| **便于实现分页** | 现代 OS 主要依赖分页而非分段 |
| **移植性好** | 大多数现代 x86 OS 使用此模型 |

### 6.3 历史背景

早期 x86（8086）使用分段是因为：
- 16 位寄存器无法直接寻址 20 位地址（1MB）
- 需要段:偏移的组合方式

现代操作系统：
- 分段被视为"历史包袱"
- Linux/Windows 都使用平坦模型 + 分页
- x86-64 甚至弱化了分段（强制平坦模型）
