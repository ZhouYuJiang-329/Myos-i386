# Phase 1 - 中断处理模块开发计划

## 1. 任务概述

**目标**: 实现完整的中断处理框架，包括 CPU 异常处理、硬件中断管理（PIC 8259A）、IDT 配置和中断服务例程（ISR）。

**重要性**: 中断是操作系统的核心机制，用于处理 CPU 异常、硬件事件（键盘、定时器、磁盘等）和系统调用。

## 3. 开发步骤

### Step 1: 设计 IDT 数据结构 (30分钟)

**任务内容**:
- 定义 IDT 门描述符结构（8字节）
- 定义 IDT 指针结构（6字节）
- 定义中断栈帧结构（`interrupt_frame`）
- 定义门类型标志（中断门、陷阱门）
- 声明 IDT 初始化函数

**关键技术点**:
- IDT 表项格式：base_lo (16) + selector (16) + always0 (8) + flags (8) + base_hi (16)
- 中断门（0x8E）：自动禁用中断（CLI）
- 陷阱门（0x8F）：不自动禁用中断
- 栈帧结构需考虑特权级切换（ESP/SS 可能不存在）

**输出文件**:
- `oskernel/kernel/idt/idt.h`

**验收标准**:
- [ ] 结构体定义正确，使用 `__attribute__((packed))`
- [ ] 常量定义符合 x86 规范
- [ ] 函数声明清晰，参数明确

---

### Step 2: 实现 IDT 初始化 (1小时)

**任务内容**:
- 实现 `idt_set_gate()` - 设置单个 IDT 门描述符
- 实现 `idt_init()` - 初始化所有 256 个 IDT 表项
- 设置 CPU 异常处理程序（ISR 0-31）
- 设置硬件中断处理程序（IRQ 0-15，映射到 ISR 32-47）
- 使用 `lidt` 指令加载 IDT

**关键技术点**:
- 清零 IDT 表（256 × 8 = 2048 字节）
- 异常处理使用中断门（自动禁用中断）
- 断点和溢出使用陷阱门（支持嵌套调试）
- 段选择子使用 0x08（内核代码段）

**输出文件**:
- `oskernel/kernel/idt/idt.c`

**验收标准**:
- [ ] 所有 256 个 IDT 表项正确初始化
- [ ] CPU 异常（0-31）有对应的处理程序
- [ ] 硬件中断（32-47）有对应的处理程序
- [ ] `lidt` 指令成功加载 IDT

---

### Step 3: 实现 ISR 汇编入口 (1.5小时)

**任务内容**:
- 创建 ISR 宏（`ISR_NOERRCODE`、`ISR_ERRCODE`）
- 创建 IRQ 宏（`IRQ`）
- 实现 `isr_common_stub` - 通用异常处理入口
- 实现 `irq_common_stub` - 通用硬件中断处理入口
- 保存/恢复所有寄存器（EAX, ECX, EDX, EBX, ESP, EBP, ESI, EDI, DS, ES, FS, GS）
- 切换到内核数据段（0x10）
- 调用 C 语言 `interrupt_handler`

**关键技术点**:
- 无错误码的异常：手动压入伪错误码（0）
- 有错误码的异常：CPU 自动压入，不需要额外操作
- 栈布局一致性：确保 `interrupt_frame` 结构与实际栈布局匹配
- **Bug 修复**：使用 `lea` 计算 frame 指针，而不是 `push esp`
- **特权级处理**：考虑 ESP/SS 可能不存在的情况

**输出文件**:
- `oskernel/kernel/idt/isr.asm`

**验收标准**:
- [ ] 所有 ISR 0-31 正确生成
- [ ] 所有 IRQ 0-15 正确生成
- [ ] 寄存器保存/恢复完整
- [ ] 正确调用 C 语言处理函数
- [ ] 使用 `iret` 正确返回

---

### Step 4: 实现 PIC 初始化 (1小时)

**任务内容**:
- 实现 `pic_init()` - 初始化 8259A PIC
- 发送 ICW1-ICW4 初始化序列
- 设置中断向量偏移（主 PIC: 0x20，从 PIC: 0x28）
- 配置级联关系（IRQ 2 连接从 PIC）
- 实现 `pic_send_eoi()` - 发送中断结束信号
- 实现 `pic_set_mask()` - 设置中断掩码
- 实现 `pic_get_irr()` / `pic_get_isr()` - 读取 IRR/ISR

**关键技术点**:
- ICW1（0x11）：开始初始化，需要 ICW4
- ICW2：设置向量偏移（主 0x20，从 0x28）
- ICW3：级联配置（主: 0x04，从: 0x02）
- ICW4（0x01）：8086 模式，正常 EOI
- EOI 命令（0x20）：通知 PIC 中断处理完成
- OCW3（0x0A/0x0B）：读取 IRR/ISR

**输出文件**:
- `oskernel/kernel/idt/pic.c`
- `oskernel/kernel/idt/pic.h`

**验收标准**:
- [ ] PIC 正确初始化，无错误
- [ ] 中断向量正确映射（IRQ 0 → 0x20，IRQ 1 → 0x21，...）
- [ ] EOI 正确发送（从 PIC 中断需要发送两次）
- [ ] 中断掩码正确设置

---

### Step 5: 实现 C 语言中断处理 (1小时)

**任务内容**:
- 实现 `interrupt_init()` - 初始化中断处理框架
- 实现 `interrupt_handler()` - 通用中断处理函数
- 实现异常处理（打印错误信息，系统停止）
- 实现硬件中断处理（调用注册的回调函数）
- 实现 `register_interrupt_handler()` - 注册自定义处理函数

**关键技术点**:
- 异常处理：打印异常名称、寄存器值、停止系统
- 硬件中断：发送 EOI，调用设备特定处理
- 键盘中断：必须读取扫描码（端口 0x60），否则无法触发下一次中断
- 定时器中断：增加系统滴答计数

**输出文件**:
- `oskernel/kernel/idt/interrupt.c`
- `oskernel/kernel/idt/interrupt.h`

**验收标准**:
- [ ] CPU 异常正确捕获并显示信息
- [ ] 硬件中断正确分发
- [ ] 可以注册自定义中断处理函数
- [ ] 键盘中断能正确读取扫描码

## 4. 测试验证

### 测试用例 1: CPU 异常处理
```c
// 触发除零异常
void test_divide_error() {
    int a = 10;
    int b = 0;
    int c = a / b;  // 应该触发 ISR 0
}
```
**预期输出**:
```
========================================
[CPU EXCEPTION] Division Error (ISR 0)
========================================
  EIP:    0xXXXX
  CS:     0x08
  EFLAGS: 0xXXXX
========================================
[FATAL] System halted due to CPU exception!
```

### 测试用例 2: 键盘中断
```c
// 启用键盘中断
pic_set_mask(1, 0);  // 启用 IRQ 1（键盘）
__asm__ __volatile__("sti");  // 启用中断

// 按下键盘按键
// 预期输出扫描码
```
**预期输出**:
```
[IRQ] Keyboard scancode: 0x1E  // 'A' 键按下
[IRQ] Keyboard scancode: 0x9E  // 'A' 键释放
```

```
**预期输出**:
```

...

## 5. 关键技术要点

### 5.1 IDT 表项格式

```
┌─────────────────────────────────────────────────────────────┐
│  Bits 0-15   │  base_lo    │  ISR 地址低 16 位              │
├─────────────────────────────────────────────────────────────┤
│  Bits 16-31  │  selector   │  段选择子（0x08）              │
├─────────────────────────────────────────────────────────────┤
│  Bits 32-39  │  always0    │  保留位，必须为 0              │
├─────────────────────────────────────────────────────────────┤
│  Bits 40-47  │  flags      │  P(1) | DPL(00) | S(0) | Type  │
├─────────────────────────────────────────────────────────────┤
│  Bits 48-63  │  base_hi    │  ISR 地址高 16 位              │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 中断栈帧布局

**无特权级切换（12字节）**:
```
┌─────────────────────┐
│  eflags             │  [esp + 8]
│  cs                 │  [esp + 4]
│  eip                │  [esp + 0]  ← 返回地址
└─────────────────────┘
```

**有特权级切换（20字节）**:
```
┌─────────────────────┐
│  ss                 │  [esp + 16]
│  esp                │  [esp + 12]
│  eflags             │  [esp + 8]
│  cs                 │  [esp + 4]
│  eip                │  [esp + 0]  ← 返回地址
└─────────────────────┘
```

### 5.3 PIC 初始化序列

```
ICW1 (0x11): 开始初始化，需要 ICW4，级联模式
    ↓
ICW2 (0x20/0x28): 设置中断向量偏移
    ↓
ICW3 (0x04/0x02): 设置级联关系
    ↓
ICW4 (0x01): 8086 模式，正常 EOI
    ↓
OCW1 (0xFF): 禁用所有中断（初始状态）
```

### 5.4 已知 Bug 和修复

| Bug | 位置 | 描述 | 修复方案 |
|-----|------|------|----------|
| Frame 指针错误 | isr.asm | `push esp` 压入的是当前 esp，不是 frame 地址 | 使用 `lea eax, [esp + offset]` |
| 特权级差异 | idt.h | `interrupt_frame` 假设总是有 esp/ss | 通过 TSS 强制使用内核栈，或动态检测 |

## 6. 风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| IDT 配置错误 | 中 | 高 | 使用 `lidt` 后验证，确保结构正确 |
| PIC 初始化失败 | 低 | 高 | 添加初始化状态检查，失败时输出错误 |
| 中断不触发 | 中 | 高 | 检查中断掩码、EFLAGS.IF 位、PIC 配置 |
| 双重故障 | 低 | 高 | 确保 ISR 正确保存/恢复寄存器，栈不溢出 |
| 键盘中断卡死 | 中 | 中 | 必须读取扫描码（0x60），发送 EOI |
