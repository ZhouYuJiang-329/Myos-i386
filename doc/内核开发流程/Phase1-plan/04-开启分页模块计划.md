# Phase 1 - 开启分页模块开发计划

## 1. 任务概述

**目标**: 实现 x86 架构下的分页机制，启用虚拟内存管理，建立内核的地址空间映射。

**重要性**: 分页是现代操作系统的核心功能，提供内存隔离、虚拟地址空间、内存保护等关键能力，是后续进程管理、内存分配、系统调用的基础。

## 3. 开发步骤

### Step 1: 设计分页数据结构 (30分钟)

**任务内容**:
- 定义页目录项结构 (pde_t) - 1024个条目
- 定义页表项结构 (pte_t) - 1024个条目
- 定义页目录和页表的物理地址（0x30000, 0x31000）
- 定义页表项标志位宏（P, RW, US 等）

**输出文件**:
- `oskernel/kernel/mm/paging.h`

**验收标准**:
- [ ] 结构体使用位域定义，共 32 位
- [ ] 使用 `__attribute__((packed))` 确保内存布局正确
- [ ] 标志位定义与 x86 手册一致

---

### Step 2: 实现临时页表初始化 (head.asm) (1小时)

**任务内容**:
- 在 head.asm 中清零页目录（4KB，地址 0x30000）
- 清零页表0（4KB，地址 0x31000）
- 建立低 1MB 的恒等映射（Identity Mapping）
- 设置页目录项[0]指向页表0

**关键技术点**:
- 恒等映射：虚拟地址 = 物理地址（内核启动需要）
- 页表项格式：物理地址[31:12] | 标志位[11:0]
- 页大小：4KB（4096 字节）
- 1MB 需要 256 个页表项（256 × 4KB = 1MB）

**输出文件**:
- 修改 `oskernel/boot/head.asm`

**验收标准**:
- [ ] 页目录和页表正确清零
- [ ] 低 1MB 恒等映射建立成功
- [ ] 页表项标志位设置正确（P=1, RW=1）

---

### Step 3: 启用分页机制 (head.asm) (30分钟)

**任务内容**:
- 设置 CR3 寄存器指向页目录（0x30000）
- 设置 CR0.PG 位（位 31）启用分页
- 使用跳转指令刷新流水线
- 调用 paging_init 完善页表

**关键技术点**:
- CR3 必须指向 4KB 对齐的页目录
- 启用分页后，所有地址都通过页表转换
- 必须保持恒等映射，否则 CPU 会崩溃

**输出文件**:
- 修改 `oskernel/boot/head.asm`

**验收标准**:
- [ ] CR3 正确设置为页目录地址
- [ ] CR0.PG 位成功设置
- [ ] 分页启用后系统继续正常运行

---

### Step 4: 实现分页初始化函数 (C代码) (1小时)

**任务内容**:
- 实现 `paging_init()` - 完善页表设置
- （可选）添加更多内存区域的映射
- （可选）设置内核高地址映射
- 验证分页是否成功启用

**关键技术点**:
- 检查 CR0.PG 位确认分页状态
- 页表修改需要刷新 TLB（使用 invlpg 指令）
- 可以扩展映射更多物理内存

**输出文件**:
- `oskernel/kernel/mm/paging.c`

**验收标准**:
- [ ] paging_init 被正确调用
- [ ] 能正确读取 CR0 验证分页状态
- [ ] 为后续扩展预留接口

## 5. 关键技术要点

### 5.1 分页机制概述

```
虚拟地址（32位）:
+--------+--------+------------+
| 目录索引 | 页表索引 | 页内偏移   |
| (10位) | (10位) |  (12位)    |
+--------+--------+------------+
    |         |         |
    v         v         v
+------------+  +------------+  +------------+
| 页目录     |  | 页表       |  | 物理页     |
| 1024项     |->| 1024项     |->| 4KB        |
| 4KB        |  | 4KB        |  |            |
+------------+  +------------+  +------------+
```

### 5.2 页目录项/页表项格式

```
Bit     名称        说明
0       P (Present)     页存在内存中（1=存在）
1       R/W             读写权限（0=只读，1=可写）
2       U/S             用户/超级用户（0=特权级，1=用户）
3       PWT             写通（Write-Through）
4       PCD             禁用缓存（Cache Disable）
5       A (Accessed)    访问位（CPU设置）
6       D (Dirty)       脏位（仅页表项，CPU设置）
7       PS/PAT          页大小/页属性表
8       G (Global)      全局页（TLB不刷新）
9-11    AVL             软件可用
12-31   地址            页表/页的物理地址[31:12]
```

### 5.3 恒等映射的重要性

```
启用分页前:
    物理地址 0x1200 -> 访问 head.asm 代码

启用分页后（无恒等映射）:
    虚拟地址 0x1200 -> 页表查找 -> ???（可能崩溃）

启用分页后（有恒等映射）:
    虚拟地址 0x1200 -> 页表查找 -> 物理地址 0x1200
    代码可以继续执行
```

**为什么需要恒等映射**：
- 启用分页后，CPU 立即开始使用虚拟地址
- 如果没有恒等映射，下一条指令的地址就会翻译错误
- 恒等映射确保内核代码在启用分页前后都能正常访问

### 5.4 控制寄存器操作

```nasm
; 设置 CR3（页目录基址）
mov eax, 0x30000    ; 页目录物理地址
mov cr3, eax        ; 加载页目录地址

; 启用分页（设置 CR0.PG）
mov eax, cr0
or eax, 0x80000000  ; 设置 PG 位（位 31）
mov cr0, eax        ; 启用分页

; 刷新流水线（重要！）
jmp .flush
.flush:
```

## 6. 风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| 页表地址未对齐 | 中 | 高 | 确保页目录和页表 4KB 对齐 |
| 缺少恒等映射 | 中 | 高 | 必须先映射内核代码所在内存 |
| 页表项标志错误 | 中 | 中 | 仔细检查 P、RW 位设置 |
| TLB 缓存问题 | 低 | 中 | 修改页表后使用 invlpg 刷新 |
| 内存区域冲突 | 低 | 高 | 确认 0x30000-0x31FFF 未被使用 |

## 7. 内存布局规划

```
物理内存布局（分页相关）:

0x00030000 - 0x00030FFF: 页目录 (4KB)
0x00031000 - 0x00031FFF: 页表0 (4KB, 映射低1MB)
0x00032000 - 0x00032FFF: （预留）页表1
...

虚拟地址空间（启用分页后）:

0x00000000 - 0x000FFFFF: 映射到物理 0-1MB（恒等映射）
0x00100000 - 0xFFFFFFFF: 未映射（访问会触发页错误）
```
