# Phase 1 - 物理内存管理模块开发计划

## 1. 任务概述

**目标**: 实现基于位图的物理内存管理器，支持内核/用户内存池分离、虚拟地址分配和页表映射。

**重要性**: 物理内存管理是操作系统的核心基础设施，所有内存分配（内核堆、用户进程、页表）都依赖于此模块。

## 3. 内存布局设计

### 3.1 物理内存布局

```
物理地址              用途                          大小
─────────────────────────────────────────────────────────────
0x00000000 ┌─────────────────────────────┐
           │  BIOS 数据区 (BDA/IVT)       │  1KB
0x00000400 ├─────────────────────────────┤
           │  空闲                        │
0x00001100 ├─ E820 内存映射表 ────────────┤  4B + 条目数据
0x00001200 ├─ 内核代码 ──────────────────┤  ~20KB
0x0009A000 ├─ 内核池位图 ────────────────┤  ~8KB
0x0009C000 ├─ 用户池位图 ────────────────┤  ~8KB
0x0009F000 ├─ 内核栈 (ESP) ─────────────┤  4KB
0x00100000 ├─ 页目录 + 页表0 ────────────┤  8KB
0x00200000 ├─ 内核物理池 (kernel_pool) ──┤  ~255MB
0x100BF000 ├─ 用户物理池 (user_pool) ────┤  ~255MB
0x1FFE0000 └─────────────────────────────┘
```

### 3.2 虚拟地址映射

```
虚拟地址                    物理地址
0x00000000 ~ 0x000FFFFF  →  0x00000000 ~ 0x000FFFFF  (恒等映射)
0xC0000000 ~ 0xC00FFFFF  →  0x00000000 ~ 0x000FFFFF  (高地址映射)
0xC0100000+              →  未映射 (内核堆区，待扩展页表)
```

## 4. 数据结构设计

### 4.1 物理内存池 (struct pool)

```c
struct pool {
   struct bitmap pool_bitmap;   // 位图，管理物理页的分配状态
   uint32_t phy_addr_start;     // 管理的物理内存起始地址
   uint32_t pool_size;          // 池的字节容量
};
```

- `kernel_pool`: 管理内核可用的物理页（从 0x200000 开始）
- `user_pool`: 管理用户进程可用的物理页（从内核池结束后开始）

### 4.2 虚拟地址池 (struct virtual_addr)

```c
struct virtual_addr {
   struct bitmap vaddr_bitmap;  // 位图，管理虚拟页的分配状态
   uint32_t vaddr_start;        // 虚拟地址起始地址 (0xC0100000)
};
```

### 4.3 页表属性常量

```c
#define PG_P_1    1    // 页存在
#define PG_P_0    0    // 页不存在
#define PG_RW_R   0    // 只读
#define PG_RW_W   2    // 可写
#define PG_US_S   0    // 系统级
#define PG_US_U   4    // 用户级
```

**输出文件**:

**验收标准**:

- [ ] 常量值与实际内存布局匹配
- [ ] 函数声明清晰

---

### Step 2: 实现物理内存池初始化 (1小时)

**任务内容**:
- 实现 `mem_pool_init()` - 初始化内核和用户物理内存池
- 从 E820 表获取总可用内存大小（使用 `get_total_memory_bytes()`）
- 计算已用内存（1MB 内存 + 256 个页表 = 2MB）
- 将空闲内存平分给内核池和用户池
- 计算位图大小并放置位图到低 1MB 空闲区域
- 调用 `bitmap_init()` 清零位图

**关键技术点**:
- 位图位置：内核池位图在 0x9A000，用户池位图紧随其后
- 位图大小：每页占 1 bit，`页数 / 8` 字节
- 低 1MB 区域由 head.asm 的页表恒等映射，可安全访问

**输出文件**:
- `oskernel/kernel/mm/memory.c`（mem_pool_init 函数）

**验收标准**:
- [ ] kernel_pool.phy_addr_start = 0x200000
- [ ] 位图正确清零
- [ ] 内核池和用户池大小合理（各约 255MB）

---

### Step 3: 实现虚拟地址分配 (1小时)

**任务内容**:
- 实现 `vaddr_get()` - 从虚拟地址池分配连续虚拟页
- 在虚拟地址位图中扫描连续空闲位
- 标记已分配的位
- 计算返回虚拟地址 = vaddr_start + bit_idx × PG_SIZE

**关键技术点**:
- 只实现了内核虚拟地址分配（PF_KERNEL）
- 用户虚拟地址分配预留接口，待用户进程实现后补充
- 位图扫描使用 `bitmap_scan()` 找连续空闲位

**输出文件**:
- `oskernel/kernel/mm/memory.c`（vaddr_get 函数）

**验收标准**:
- [ ] 能正确分配连续虚拟页
- [ ] 分配失败时返回 NULL
- [ ] 位图状态正确更新

---

### Step 4: 实现物理页分配 (30分钟)

**任务内容**:
- 实现 `palloc()` - 从物理内存池分配一个物理页
- 在物理页位图中扫描空闲位
- 标记为已用
- 计算物理地址 = bit_idx × PG_SIZE + phy_addr_start

**关键技术点**:
- 每次只分配一个物理页
- 分配的物理页不保证连续（通过页表映射实现虚拟连续）
- 位图操作需要保证原子性（后续可加锁）

**输出文件**:
- `oskernel/kernel/mm/memory.c`（palloc 函数）

**验收标准**:
- [ ] 能正确分配物理页
- [ ] 返回的物理地址在池的管理范围内
- [ ] 位图状态正确更新

---

### Step 5: 实现页表映射 (1.5小时)

**任务内容**:
- 实现 `pde_ptr()` - 获取虚拟地址对应的页目录项指针
- 实现 `pte_ptr()` - 获取虚拟地址对应的页表项指针
- 实现 `page_table_add()` - 在页表中建立虚拟地址到物理地址的映射

**关键技术点**:
- 递归页目录自映射：页目录第 1023 项指向页目录自身
- `pde_ptr(vaddr)`: 访问 `0xFFFFF000 + PDE_IDX × 4`
- `pte_ptr(vaddr)`: 访问 `0xFFC00000 + PDE_IDX × 1024 + PTE_IDX × 4`
- 新建页表时需要：
  1. 从内核池分配一个物理页作为新页表
  2. 用 `memset` 清零该页
  3. 设置页目录项指向新页表
  4. 设置页表项完成映射

**输出文件**:
- `oskernel/kernel/mm/memory.c`（pde_ptr, pte_ptr, page_table_add 函数）

**验收标准**:
- [ ] 页目录项和页表项指针计算正确
- [ ] 新页表正确分配并清零
- [ ] 映射关系正确建立
- [ ] 不破坏已有的页表映射

---

### Step 6: 实现内存分配接口 (1小时)

**任务内容**:
- 实现 `malloc_page()` - 分配 pg_cnt 个连续虚拟页并映射物理页
- 实现 `get_kernel_pages()` - 从内核池分配并清零

**分配流程**:
```
get_kernel_pages(pg_cnt)
  → malloc_page(PF_KERNEL, pg_cnt)
      → vaddr_get()      // 1. 分配虚拟地址
      → palloc()         // 2. 分配物理页（逐个）
      → page_table_add() // 3. 建立映射（逐个）
  → memset()             // 4. 清零
```

**关键技术点**:
- 虚拟地址连续，物理地址可以不连续
- 每个虚拟页单独映射一个物理页
- 失败时需要回滚已分配的资源（待完善）

**输出文件**:
- `oskernel/kernel/mm/memory.c`（malloc_page, get_kernel_pages 函数）

**验收标准**:
- [ ] 能成功分配多页内存
- [ ] 返回的虚拟地址可正常读写
- [ ] 分配后内存已清零

## 7. 已知问题与待完善

### 7.1 malloc_page 缺少回滚机制
**问题**: 分配多个页时，如果中途 `palloc` 失败，已分配的虚拟页和物理页不会被回收。
**影响**: 虚拟地址位图泄漏，物理页泄漏。
**修复方案**: 失败时遍历已分配的页，清除位图和页表项。

### 7.2 ASSERT/PANIC 未实现
**问题**: 代码中引用了 ASSERT 和 PANIC 宏，但未定义。
**当前处理**: 已删除相关调用。
**待做**: 实现简易断言机制（打印错误信息 + 死循环）。

### 7.3 内核堆区页表未扩展
**问题**: `K_HEAP_START = 0xC0100000` 目前没有页表映射。
**影响**: `get_kernel_pages()` 分配的虚拟地址无法访问。
**待做**: 扩展 head.asm 的页表，映射 0xC0100000+ 的虚拟地址。

### 7.4 位图地址显示异常
**问题**: `serial_printf("%x")` 对 `int` 参数做符号扩展，导致位图地址显示为 0xc009bfd7 等非对齐值。
**影响**: 仅影响显示，不影响实际功能。
**修复**: 使用 `%u` 或强制转换为 `uint32_t`。
