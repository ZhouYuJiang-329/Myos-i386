# 中断处理模块代码详解

## 1. 模块概述

中断处理模块负责：
1. **IDT 管理**：配置 256 个中断描述符表项
2. **CPU 异常处理**：捕获和处理 32 种 CPU 异常
3. **硬件中断管理**：通过 8259A PIC 管理 16 个硬件中断
4. **中断分发**：将中断分发到对应的处理函数

---

## 2. 核心数据结构

### 2.1 IDT 门描述符结构

```c
// oskernel/kernel/idt/idt.h
struct idt_entry {
    uint16_t base_lo;      // ISR 低16位地址 (Bits 0-15)
    uint16_t selector;     // 段选择子 (Bits 16-31)
    uint8_t  always0;      // 保留位，始终为0 (Bits 32-39)
    uint8_t  flags;        // 门描述符类型和属性 (Bits 40-47)
    uint16_t base_hi;      // ISR 高16位地址 (Bits 48-63)
} __attribute__((packed));
```

**内存布局（8字节）**:
```
Bit:     0-15      16-31      32-39      40-47      48-63
      +--------+----------+----------+----------+--------+
      |base_lo | selector |  always0 |  flags   |base_hi |
      +--------+----------+----------+----------+--------+
Byte:    0-1       2-3        4          5         6-7
```

**字段说明**:

| 字段 | 大小 | 说明 |
|------|------|------|
| `base_lo` | 16位 | ISR 地址低16位 |
| `selector` | 16位 | 代码段选择子（通常0x08） |
| `always0` | 8位 | 保留位，必须为0 |
| `flags` | 8位 | P(1) \| DPL(2) \| S(1) \| Type(4) |
| `base_hi` | 16位 | ISR 地址高16位 |

### 2.2 IDT 指针结构

```c
struct idt_ptr {
    uint16_t limit;        // IDT 界限（字节数 - 1）
    uint32_t base;         // IDT 基地址
} __attribute__((packed));
```

**用途**：`lidt` 指令从此结构加载 IDTR 寄存器（6字节）

### 2.3 中断栈帧结构

```c
struct interrupt_frame {
    // CPU 自动压入（总是存在）
    uint32_t eip;          // 返回地址
    uint32_t cs;           // 代码段选择子
    uint32_t eflags;       // 标志寄存器

    // CPU 自动压入（仅特权级切换时）
    uint32_t esp;          // 旧栈指针（可能不存在）
    uint32_t ss;           // 旧栈段（可能不存在）
} __attribute__((packed));
```

**重要说明**：
- `esp` 和 `ss` 只在特权级切换时存在
- 内核态中断（无切换）：栈帧 12 字节
- 用户态中断（有切换）：栈帧 20 字节

## 3. IDT 初始化详解

### 3.1 设置 IDT 门描述符

```c
void idt_set_gate(uint8_t vector, uint32_t handler, 
                  uint16_t selector, uint8_t type_attr) {
    // 提取 ISR 地址的低16位和高16位
    idt[vector].base_lo = handler & 0xFFFF;
    idt[vector].base_hi = (handler >> 16) & 0xFFFF;

    // 设置段选择子和属性
    idt[vector].selector = selector;
    idt[vector].always0 = 0;
    idt[vector].flags = type_attr;
}
```

**参数说明**:

| 参数 | 说明 | 典型值 |
|------|------|--------|
| `vector` | 中断向量号 (0-255) | 0-31: 异常, 32-47: IRQ |
| `handler` | ISR 函数地址 | `isr0`, `irq0` 等 |
| `selector` | 代码段选择子 | 0x08 (内核代码段) |
| `type_attr` | 门类型和属性 | 0x8E (中断门), 0x8F (陷阱门) |

### 3.2 门类型标志

```c
#define IDT_GATE_INTERRUPT  0x8E  // 1000 1110
#define IDT_GATE_TRAP       0x8F  // 1000 1111
```

**标志位解析**:
```
Bit 7 (P): 1 = 段存在
Bit 6-5 (DPL): 00 = 特权级0
Bit 4 (S): 0 = 系统段
Bit 3-0 (Type): 
    1110 (0xE) = 32位中断门
    1111 (0xF) = 32位陷阱门
```

**中断门 vs 陷阱门**:

| 特性 | 中断门 | 陷阱门 |
|------|--------|--------|
| 自动禁用中断 | ✅ 是（清 IF 位） | ❌ 否 |
| 用途 | 普通中断 | 调试、断点 |
| 典型使用 | ISR 0-2, 4-31 | ISR 3 (断点), ISR 4 (溢出) |

### 3.3 IDT 初始化流程

```c
void idt_init(void) {
    // 1. 设置 IDT 指针
    idtp.limit = sizeof(idt) - 1;  // 256 * 8 - 1 = 2047
    idtp.base = (uint32_t)&idt;

    // 2. 清零 IDT 表
    for (uint16_t i = 0; i < sizeof(idt); i++) {
        ((uint8_t*)&idt)[i] = 0;
    }

    // 3. 设置 CPU 异常处理程序 (ISR 0-31)
    idt_set_gate(0, (uint32_t)isr0, 0x08, IDT_GATE_INTERRUPT);
    idt_set_gate(1, (uint32_t)isr1, 0x08, IDT_GATE_INTERRUPT);
    // ... ISR 2-31

    // 4. 设置硬件中断处理程序 (IRQ 0-15 → ISR 32-47)
    idt_set_gate(32, (uint32_t)irq0, 0x08, IDT_GATE_INTERRUPT);
    idt_set_gate(33, (uint32_t)irq1, 0x08, IDT_GATE_INTERRUPT);
    // ... IRQ 2-15

    // 5. 加载 IDT
    __asm__ __volatile__("lidt %0" : : "m"(idtp));
}
```

**中断向量分配**:

| 向量号 | 类型 | 说明 |
|--------|------|------|
| 0-31 | CPU 异常 | 除法错误、页错误、一般保护错误等 |
| 32-47 | 硬件中断 | IRQ 0-15（经 PIC 映射） |
| 48-255 | 可用 | 系统调用、自定义中断 |

## 4. ISR 汇编入口详解

### 4.1 ISR 宏定义

```nasm
; 无错误码的异常处理程序宏
%macro ISR_NOERRCODE 1
global isr%1
isr%1:
    push dword 0        ; 压入伪错误码（CPU 没有自动压入）
    push dword %1       ; 压入中断向量号
    jmp isr_common_stub ; 跳转到通用处理程序
%endmacro

; 有错误码的异常处理程序宏
%macro ISR_ERRCODE 1
global isr%1
isr%1:
    ; 错误码已经被 CPU 压入，不需要再压入
    push dword %1       ; 压入中断向量号
    jmp isr_common_stub
%endmacro
```

**使用示例**:
```nasm
ISR_NOERRCODE 0     ; 生成 isr0: 除法错误（无错误码）
ISR_ERRCODE 8       ; 生成 isr8: 双重故障（有错误码）
ISR_ERRCODE 14      ; 生成 isr14: 页错误（有错误码）
```

### 4.2 有/无错误码的区别

**无错误码的异常**（CPU 不自动压入错误码）:
```
中断发生时 CPU 压入：
┌───────────┐
│  eflags   │
│  cs       │
│  eip      │ ← 返回地址
└───────────┘

ISR_NOERRCODE 压入：
┌───────────┐
│  0        │ ← 伪错误码
│  vector   │ ← 中断向量号
└───────────┘
```

**有错误码的异常**（CPU 自动压入错误码）:
```
中断发生时 CPU 压入：
┌───────────┐
│  eflags   │
│  cs       │
│  eip      │ ← 返回地址
│  error    │ ← 错误码（CPU 自动压入）
└───────────┘

ISR_ERRCODE 压入：
┌───────────┐
│  vector   │ ← 中断向量号
└───────────┘
```

### 4.3 通用 ISR 处理程序

```nasm
isr_common_stub:
    ; 1. 保存通用寄存器
    push eax
    push ecx
    push edx
    push ebx
    push ebp
    push esi
    push edi

    ; 2. 保存数据段寄存器
    push ds
    push es
    push fs
    push gs

    ; 3. 切换到内核数据段
    mov ax, 0x10        ; 内核数据段选择子
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax

    ; 4. 调用 C 语言处理函数
    ; 栈布局分析（push gs 后）：
    ; [esp+0]   gs
    ; [esp+4]   fs
    ; [esp+8]   es
    ; [esp+12]  ds
    ; [esp+16]  edi
    ; [esp+20]  esi
    ; [esp+24]  ebp
    ; [esp+28]  ebx
    ; [esp+32]  edx
    ; [esp+36]  ecx
    ; [esp+40]  eax
    ; [esp+44]  interrupt_number
    ; [esp+48]  error_code
    ; [esp+52]  eip
    ; [esp+56]  cs
    ; [esp+60]  eflags
    
    push dword [esp + 44]   ; 参数2: interrupt_number
    push esp                ; 参数1: frame 指针
    call interrupt_handler
    add esp, 8              ; 清理参数

    ; 5. 恢复数据段寄存器
    pop gs
    pop fs
    pop es
    pop ds

    ; 6. 恢复通用寄存器
    pop edi
    pop esi
    pop ebp
    pop ebx
    pop edx
    pop ecx
    pop eax

    ; 7. 清理错误码和中断向量号
    add esp, 8

    ; 8. 中断返回
    iret
```

### 4.4 栈布局详解

**完整栈布局（从中断发生到调用 C 函数）**:

```
高地址
┌─────────────────┐
│     eflags      │ ← CPU 自动压入
│     cs          │ ← CPU 自动压入
│     eip         │ ← CPU 自动压入（返回地址）
│   error_code    │ ← CPU 自动压入（某些异常）
│  int_number     │ ← ISR 宏压入
│   pseudo_err    │ ← ISR_NOERRCODE 压入（0）
├─────────────────┤
│     eax         │ ← isr_common_stub 保存
│     ecx         │
│     edx         │
│     ebx         │
│     ebp         │
│     esi         │
│     edi         │
│     ds          │
│     es          │
│     fs          │
│     gs          │ ← esp 指向这里（调用 C 前）
├─────────────────┤
│  int_number     │ ← 参数2（复制）
│    frame        │ ← 参数1（当前 esp）
└─────────────────┘ ← 调用 interrupt_handler 时的 esp
低地址
```

### 4.5 已知 Bug 说明

```nasm
; 当前代码（有 Bug）
push dword [esp + 44]   ; interrupt_number
push esp                ; ❌ frame 指针错误！
```

**问题**：`push esp` 压入的是当前 esp 值（指向刚压入的参数），不是 `interrupt_frame` 的起始地址。

**修复方案**:
```nasm
; 计算 frame 指针（指向 eip）
lea eax, [esp + 48]     ; 跳过保存的寄存器 + int_number + error_code
push dword [eax - 4]    ; interrupt_number
push eax                ; ✅ 正确的 frame 指针
```

## 5. PIC 初始化详解

### 5.1 PIC 端口定义

```c
#define PIC_MASTER_COMMAND     0x20    // 主 PIC 命令端口
#define PIC_MASTER_DATA        0x21    // 主 PIC 数据端口
#define PIC_SLAVE_COMMAND      0xA0    // 从 PIC 命令端口
#define PIC_SLAVE_DATA         0xA1    // 从 PIC 数据端口
```

**端口功能**:

| 端口 | 读写 | 功能 |
|------|------|------|
| 0x20 | 写 | 发送命令（ICW, OCW, EOI） |
| 0x20 | 读 | 读取 IRR/ISR（需先发送 OCW3） |
| 0x21 | 读写 | 设置/读取中断掩码（OCW1） |
| 0xA0/0xA1 | 同上 | 从 PIC |

### 5.2 初始化命令字（ICW）

#### ICW1 - 开始初始化

```c
outb(PIC_MASTER_COMMAND, PIC_ICW1_INIT | PIC_ICW1_ICW4);
// 值: 0x11 = 0001 0001
```

**位定义**:
```
Bit 0 (ICW4): 1 = 需要 ICW4
Bit 1 (SNGL): 0 = 级联模式
Bit 2 (ADI):  0 = 调用地址间隔 8 字节
Bit 3 (LTIM): 0 = 边缘触发模式
Bit 4:        1 = 初始化命令（必须为1）
```

#### ICW2 - 中断向量偏移

```c
outb(PIC_MASTER_DATA, 0x20);   // 主 PIC: IRQ 0-7 → 向量 0x20-0x27
outb(PIC_SLAVE_DATA, 0x28);    // 从 PIC: IRQ 0-7 → 向量 0x28-0x2F
```

#### ICW3 - 级联配置

```c
// 主 PIC: 从 PIC 连接到 IRQ 2
outb(PIC_MASTER_DATA, 1 << 2);  // 值: 0x04 = 0000 0100

// 从 PIC: 连接到主 PIC 的 IRQ 2
outb(PIC_SLAVE_DATA, 2);        // 值: 0x02
```

**级联关系**:
```
        CPU
         │
    ┌────┴────┐
    │  主 PIC  │ ← 端口 0x20/0x21
    │ (IRQ 0-7)│
    └────┬────┘
         │ IRQ 2（级联）
    ┌────┴────┐
    │  从 PIC  │ ← 端口 0xA0/0xA1
    │ (IRQ 8-15)│
    └─────────┘
```

#### ICW4 - 工作模式

```c
outb(PIC_MASTER_DATA, PIC_ICW4_8086);  // 值: 0x01
```

**位定义**:
```
Bit 0 (μPM): 1 = 8086/8088 模式
Bit 1 (AEOI): 0 = 正常 EOI 模式
Bit 2-3: 0 = 非缓冲模式
Bit 4 (SFNM): 0 = 完全嵌套模式
```

### 5.3 完整初始化序列

```c
void pic_init(uint8_t master_offset, uint8_t slave_offset) {
    // ICW1: 开始初始化
    outb(PIC_MASTER_COMMAND, 0x11);
    outb(PIC_SLAVE_COMMAND, 0x11);
    io_wait();

    // ICW2: 设置向量偏移
    outb(PIC_MASTER_DATA, master_offset);
    outb(PIC_SLAVE_DATA, slave_offset);
    io_wait();

    // ICW3: 级联配置
    outb(PIC_MASTER_DATA, 0x04);   // 主: IRQ 2 有从片
    outb(PIC_SLAVE_DATA, 0x02);    // 从: 连接到主片 IRQ 2
    io_wait();

    // ICW4: 8086 模式，正常 EOI
    outb(PIC_MASTER_DATA, 0x01);
    outb(PIC_SLAVE_DATA, 0x01);
    io_wait();

    // 禁用所有中断（初始状态）
    outb(PIC_MASTER_DATA, 0xFF);
    outb(PIC_SLAVE_DATA, 0xFF);
}
```

### 5.4 EOI（中断结束）命令

```c
void pic_send_eoi(uint8_t irq) {
    // 从 PIC 的中断需要同时发送 EOI 给主 PIC
    if (irq >= 8) {
        outb(PIC_SLAVE_COMMAND, 0x20);  // 从 PIC EOI
    }
    outb(PIC_MASTER_COMMAND, 0x20);      // 主 PIC EOI
}
```

**为什么从 PIC 需要发送两次 EOI？**
```
IRQ 8-15 的中断路径：
设备 → 从 PIC → 主 PIC IRQ 2 → CPU

EOI 路径：
CPU → 从 PIC EOI（清除从 PIC 的 ISR 位）
    → 主 PIC EOI（清除主 PIC 的 ISR 位）
```

### 5.5 读取 IRR/ISR

```c
// 读取 IRR（中断请求寄存器）
uint16_t pic_get_irr(void) {
    outb(PIC_MASTER_COMMAND, 0x0A);  // OCW3: RR=1, RIS=0
    outb(PIC_SLAVE_COMMAND, 0x0A);
    
    uint8_t master = inb(PIC_MASTER_COMMAND);
    uint8_t slave = inb(PIC_SLAVE_COMMAND);
    
    return (slave << 8) | master;
}

// 读取 ISR（中断服务寄存器）
uint16_t pic_get_isr(void) {
    outb(PIC_MASTER_COMMAND, 0x0B);  // OCW3: RR=1, RIS=1
    outb(PIC_SLAVE_COMMAND, 0x0B);
    
    uint8_t master = inb(PIC_MASTER_COMMAND);
    uint8_t slave = inb(PIC_SLAVE_COMMAND);
    
    return (slave << 8) | master;
}
```

**OCW3 命令解析**:
```
0x0A = 0000 1010: RR=1, RIS=0 → 读取 IRR
0x0B = 0000 1011: RR=1, RIS=1 → 读取 ISR
```

## 6. C 语言中断处理详解

### 6.1 中断处理函数注册

```c
// 中断处理函数指针数组
static interrupt_handler_t interrupt_handlers[256] = {0};

// 注册处理函数
int interrupt_register_handler(uint8_t vector, interrupt_handler_t handler) {
    if (vector >= 256) return -1;
    interrupt_handlers[vector] = handler;
    return 0;
}
```

### 6.2 通用中断处理函数

```c
void interrupt_handler(struct interrupt_frame* frame, 
                       uint32_t interrupt_number) {
    // 1. 检查是否有自定义处理函数
    if (interrupt_number < 256 && 
        interrupt_handlers[interrupt_number] != NULL) {
        interrupt_handlers[interrupt_number](frame);
        return;
    }

    // 2. CPU 异常处理 (0-31)
    if (interrupt_number < 32) {
        handle_exception(frame, interrupt_number);
        return;
    }

    // 3. 硬件中断处理 (32-47)
    if (interrupt_number >= 32 && interrupt_number < 48) {
        handle_irq(frame, interrupt_number);
        return;
    }
}
```

### 6.3 CPU 异常处理

```c
static const char* exception_names[] = {
    "Division Error",           // 0
    "Debug Exception",          // 1
    "Non-Maskable Interrupt",   // 2
    "Breakpoint",               // 3
    // ... 更多异常
};

static void handle_exception(struct interrupt_frame* frame, 
                             uint32_t vector) {
    serial_printf("[CPU EXCEPTION] %s (ISR %d)\n", 
                  exception_names[vector], vector);
    serial_printf("  EIP:    0x%x\n", frame->eip);
    serial_printf("  CS:     0x%x\n", frame->cs);
    serial_printf("  EFLAGS: 0x%x\n", frame->eflags);
    
    // 严重异常，停止系统
    while (1) {
        __asm__ __volatile__("cli; hlt");
    }
}
```

### 6.4 硬件中断处理

```c
static void handle_irq(struct interrupt_frame* frame, 
                       uint32_t vector) {
    uint8_t irq = vector - 32;
    
    // 特殊处理：键盘中断
    if (irq == 1) {
        uint8_t scancode = inb(0x60);
        serial_printf("[IRQ] Keyboard: 0x%x\n", scancode);
    }
    
    // 发送 EOI
    pic_send_eoi(irq);
}
```

**重要**：键盘中断必须读取扫描码（端口 0x60），否则键盘控制器保持 IRQ 线高电平，无法触发下一次中断。

## 7. 中断处理流程图

```
中断发生
    │
    ▼
CPU 自动压栈:
  - eflags, cs, eip
  - [error_code]（某些异常）
    │
    ▼
查找 IDT[vector]
    │
    ▼
跳转到 ISR 入口
    │
    ▼
ISR 宏压栈:
  - 伪错误码（0）
  - 中断向量号
    │
    ▼
isr_common_stub:
  1. 保存通用寄存器
  2. 保存段寄存器
  3. 切换内核数据段
    │
    ▼
调用 interrupt_handler(frame, vector)
    │
    ▼
C 语言处理:
  - 异常: 打印信息，停止系统
  - IRQ: 设备处理，发送 EOI
    │
    ▼
返回 isr_common_stub
    │
    ▼
恢复段寄存器
恢复通用寄存器
清理栈
    │
    ▼
iret（返回被中断代码）
```

## 8. 关键设计决策

### 8.1 为什么使用汇编 ISR 入口？

- **寄存器保存**：C 语言无法精确控制所有寄存器保存
- **栈布局**：需要精确控制栈布局以匹配 `interrupt_frame`
- **特权级切换**：汇编可以处理复杂的段切换
- **iret 指令**：必须使用汇编执行中断返回

### 8.2 为什么区分 ISR_NOERRCODE 和 ISR_ERRCODE？

- **栈一致性**：确保所有 ISR 入口的栈布局一致
- **简化处理**：通用处理程序可以统一处理错误码
- **CPU 行为**：某些异常自动压入错误码，某些不压入

### 8.3 为什么 PIC 需要级联？

- **中断数量**：单个 8259A 只有 8 个 IRQ
- **系统需求**：x86 系统需要 16 个 IRQ
- **硬件设计**：主 PIC 的 IRQ 2 专门用于级联从 PIC

## 9. 调试技巧

### 9.1 验证 IDT 加载

```c
void debug_idt(void) {
    struct idt_ptr idtp;
    __asm__ __volatile__("sidt %0" : "=m"(idtp));
    
    serial_printf("IDT Base: 0x%x, Limit: %d\n", 
                  idtp.base, idtp.limit);
}
```

### 9.2 验证中断触发

```c
// 触发除零异常测试
void test_divide_error(void) {
    int a = 10, b = 0;
    int c = a / b;  // 应该触发 ISR 0
}
```

### 9.3 检查 PIC 状态

```c
void debug_pic(void) {
    uint16_t mask = pic_get_mask();
    uint16_t irr = pic_get_irr();
    uint16_t isr = pic_get_isr();
    
    serial_printf("PIC Mask: 0x%x\n", mask);
    serial_printf("PIC IRR:  0x%x\n", irr);
    serial_printf("PIC ISR:  0x%x\n", isr);
}
```
