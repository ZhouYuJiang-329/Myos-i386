# 开启分页模块代码详解

## 1. 模块概述

开启分页模块负责：
1. **页表初始化**：建立虚拟地址到物理地址的映射关系
2. **分页启用**：配置 CR3 和 CR0 寄存器启用分页机制
3. **恒等映射**：确保内核代码在分页启用前后都能正常访问

---

## 2. 核心数据结构

### 2.1 页目录项 (PDE - Page Directory Entry)

```c
// oskernel/kernel/mm/paging.h
typedef struct {
    uint32_t present : 1;         // 存在位
    uint32_t writable : 1;        // 读写位（1=可写）
    uint32_t user : 1;           // 用户/超级visor位
    uint32_t write_through : 1;  // 写通位
    uint32_t cache_disable : 1;  // 缓存禁用位
    uint32_t accessed : 1;       // 访问位
    uint32_t dirty : 1;          // 脏位（对PDE未使用）
    uint32_t page_size : 1;      // 页大小（0=4KB, 1=4MB）
    uint32_t global : 1;         // 全局位
    uint32_t available : 3;      // 可用位（软件使用）
    uint32_t page_table_addr : 20;  // 页表物理地址 >> 12
} __attribute__((packed)) pde_t;
```

**设计说明**：
- 使用 C 语言位域精确控制每个字段的位数
- `__attribute__((packed))` 确保结构体大小为 4 字节（32位）
- `page_table_addr` 存储页表物理地址的高 20 位（低 12 位必须为 0，即 4KB 对齐）

### 2.2 页表项 (PTE - Page Table Entry)

```c
typedef struct {
    uint32_t present : 1;         // 存在位
    uint32_t writable : 1;        // 读写位（1=可写）
    uint32_t user : 1;           // 用户/超级visor位
    uint32_t write_through : 1;  // 写通位
    uint32_t cache_disable : 1;  // 缓存禁用位
    uint32_t accessed : 1;       // 访问位
    uint32_t dirty : 1;          // 脏位
    uint32_t pat : 1;            // 页属性表位
    uint32_t global : 1;         // 全局位
    uint32_t available : 3;      // 可用位（软件使用）
    uint32_t page_addr : 20;     // 页物理地址 >> 12
} __attribute__((packed)) pte_t;
```

**PDE 与 PTE 的区别**：
- PDE 指向页表，PTE 指向物理页
- PDE 的 `dirty` 位未使用，PTE 的 `dirty` 位表示页是否被写入
- PDE 的 `page_size` 位用于选择 4KB 或 4MB 页

### 2.3 页表项标志位宏

```nasm
; oskernel/boot/head.asm
PG_P  equ   1b          ; Present - 页存在内存中
PG_RW_R  equ  00b       ; Read-Only - 只读
PG_RW_W  equ  10b       ; Read/Write - 可读写
PG_US_S  equ  000b      ; Supervisor - 特权级
PG_US_U  equ  100b      ; User - 用户级
```

**标志位组合示例**：
```
PG_US_U | PG_RW_W | PG_P = 0b111 = 0x7
表示：用户可访问、可读写、页存在
```

## 3. 分页机制详解

### 3.1 两级页表结构

```
32位虚拟地址划分:
+------------+------------+------------+
|  目录索引   |  页表索引   |  页内偏移   |
|  (10位)    |  (10位)    |  (12位)    |
+------------+------------+------------+
     |            |            |
     v            v            v
+------------+  +------------+  +------------+
| 页目录     |  | 页表       |  | 物理页     |
| 1024项     |->| 1024项     |->| 4096字节   |
| 4KB        |  | 4KB        |  |            |
+------------+  +------------+  +------------+
   CR3指向       PDE指向        PTE指向
```

**地址计算**：
```
虚拟地址 0x00123456:
  目录索引 = (0x00123456 >> 22) & 0x3FF = 0x00
  页表索引 = (0x00123456 >> 12) & 0x3FF = 0x123
  页内偏移 = 0x00123456 & 0xFFF = 0x456
```

### 3.2 页目录和页表内存布局

```
物理内存布局:

0x00030000 - 0x00030FFF: 页目录 (Page Directory)
  + 1024 个 PDE，每个 4 字节
  + 共 4KB
  
0x00031000 - 0x00031FFF: 页表0 (Page Table 0)
  + 1024 个 PTE，每个 4 字节
  + 共 4KB
  + 映射虚拟地址 0x00000000 - 0x003FFFFF

页目录项[0] -> 页表0 (0x31000)
页目录项[1] -> （未设置）
...
页目录项[1023] -> （未设置）
```

## 4. 汇编代码详解 (head.asm)

### 4.1 页目录清零

```nasm
; 清零页目录 (4KB)
xor eax, eax
mov edi, 0x30000  ; PAGE_DIR_PHYS - 页目录物理地址
mov ecx, 1024     ; 1024个条目，每个4字节，共4KB
.clear_page_dir:
    mov [edi], eax    ; 将0写入当前位置
    add edi, 4        ; 移动到下一个条目
    dec ecx           ; 计数减1
    jnz .clear_page_dir  ; 如果不为0，继续循环
```

**操作说明**：
- 使用 `xor eax, eax` 快速清零 EAX 寄存器
- EDI 作为目的地址指针，每次增加 4 字节
- ECX 作为循环计数器，共 1024 次
- 清零后所有 PDE 的 `present` 位为 0，表示未映射

### 4.2 页表清零

```nasm
; 清零页表0 (4KB)
xor eax, eax
mov edi, 0x31000  ; PAGE_TABLE0_PHYS - 页表0物理地址
mov ecx, 1024     ; 1024个条目
.clear_page_table:
    mov [edi], eax
    add edi, 4
    dec ecx
    jnz .clear_page_table
```

### 4.3 建立恒等映射

```nasm
; 映射低1MB (256个4KB页)
; 页表0覆盖: 0x00000000 - 0x000FFFFF
mov edi, 0x31000  ; 页表0起始地址
xor ebx, ebx      ; 物理地址 = 0，从0开始映射

.map_low_1mb:
    ; 设置页表项: present=1, writable=1, user=1
    mov eax, ebx
    or eax, PG_US_U | PG_RW_W | PG_P    ; 添加标志位
    mov [edi], eax                      ; 写入页表项

    add ebx, 0x1000   ; 下一个4KB页 (4096 = 0x1000)
    add edi, 4        ; 下一个页表项
    cmp ebx, 0x100000 ; 是否到达1MB
    jl .map_low_1mb   ; 小于则继续循环
```

**映射过程详解**：

| 迭代 | EBX (物理地址) | EDI (页表项地址) | PTE 值 | 映射范围 |
|------|----------------|------------------|--------|----------|
| 1 | 0x00000 | 0x31000 | 0x000007 | 0x00000-0x00FFF |
| 2 | 0x01000 | 0x31004 | 0x001007 | 0x01000-0x01FFF |
| ... | ... | ... | ... | ... |
| 256 | 0xFF000 | 0x313FC | 0x0FF007 | 0xFF000-0xFFFFF |

**恒等映射的意义**：
```
虚拟地址 0x00000 -> 页表查找 -> 物理地址 0x00000
虚拟地址 0x01000 -> 页表查找 -> 物理地址 0x01000
...
虚拟地址 0xFF000 -> 页表查找 -> 物理地址 0xFF000
```

### 4.4 设置页目录项

```nasm
; 设置页目录项[0]指向页表0
mov eax, 0x31000  ; PAGE_TABLE0_PHYS - 页表0物理地址
or eax, PG_US_U | PG_RW_W | PG_P    ; 添加标志位
mov [0x30000], eax                  ; 写入页目录项[0]
```

**PDE 值计算**：
```
页表0地址 = 0x31000
标志位 = PG_US_U | PG_RW_W | PG_P = 0x7
PDE[0] = 0x31000 | 0x7 = 0x31007

二进制: 0x00031007
        0000 0000 0000 0011 0001 0000 0000 0111
        |<---- 页表地址[31:12] ---->| |标志|
```

### 4.5 启用分页

```nasm
; 设置CR3指向页目录
mov eax, 0x30000  ; PAGE_DIR_PHYS
mov cr3, eax
```

**CR3 寄存器**：
- 存储页目录的物理地址
- 低 12 位必须为 0（4KB 对齐）
- CPU 使用 CR3 找到页目录，开始地址转换

```nasm
; 启用分页（设置CR0.PG位）
mov eax, cr0
or eax, 0x80000000    ; 设置 PG 位（位 31）
mov cr0, eax
```

**CR0 寄存器标志位**：
```
Bit 31 (PG): 分页启用
Bit 0 (PE): 保护模式启用

CR0 = 0x80000011 表示：
  - 分页已启用 (PG=1)
  - 保护模式已启用 (PE=1)
  - 协处理器监控 (EM=0, ET=1)
```

```nasm
; 跳转刷新流水线
jmp .flush
.flush:
```

**为什么需要跳转**：
- 启用分页后，CPU 需要刷新指令预取队列
- 跳转指令强制 CPU 清空流水线，使用新的地址转换机制
- 这是启用分页后的标准做法

## 5. C 语言分页初始化

### 5.1 paging_init 函数

```c
// oskernel/kernel/mm/paging.c
#include "paging.h"

void paging_init(void) {
    // 页目录和页表已在head.asm中设置好基本的恒等映射（低1MB）
    // 这里可以添加更多映射，例如：
    // - 高地址内存映射
    // - 内核高地址映射
    // - 用户空间映射

    // 目前只保留基本映射，后续可以扩展
}
```

**设计意图**：
- `head.asm` 在启用分页前完成最小化设置（低 1MB 恒等映射）
- `paging_init` 在分页启用后执行，可以安全地修改页表
- 为后续扩展预留接口

### 5.2 验证分页启用

```c
// 在 main.c 中验证
uint32_t cr0;
__asm__ __volatile__("mov %%cr0, %0" : "=r"(cr0));
serial_printf("CR0: 0x%x\n", cr0);

if (cr0 & 0x80000000) {
    serial_puts("Paging enabled successfully!\n");
} else {
    serial_puts("ERROR: Paging not enabled!\n");
}
```

## 7. 关键设计决策

### 7.1 为什么只在 head.asm 中设置最小映射？

- **安全启动**：启用分页前必须确保代码能继续执行
- **恒等映射足够**：内核代码在低 1MB，恒等映射即可访问
- **C 语言扩展**：启用分页后可以在 C 代码中安全地修改页表

### 7.2 为什么选择 0x30000 和 0x31000？

```
内存布局考虑:
0x00000 - 0x0FFFF: 保留（中断向量表、BIOS数据）
0x10000 - 0x1FFFF: 内核代码和数据
0x20000 - 0x2FFFF: PMM 位图
0x30000 - 0x30FFF: 页目录（4KB）
0x31000 - 0x31FFF: 页表0（4KB）
```

- 这些地址在内核之后，不会被内核代码覆盖
- 4KB 对齐，符合页表对齐要求
- 与 PMM 位图（0x20000）不冲突

### 7.3 为什么需要用户/超级用户标志？

```nasm
PG_US_U  equ  100b    ; User - 用户级可访问
PG_US_S  equ  000b    ; Supervisor - 仅特权级可访问
```

- **保护模式配合**：与 x86 特权级（Ring 0-3）配合
- **内核保护**：内核页设置为 Supervisor，用户代码无法访问
- **用户空间**：用户页设置为 User，允许用户代码访问

## 9. 扩展方向

1. **高内存映射**：映射 1MB 以上的物理内存
2. **内核高地址映射**：将内核映射到高地址（如 0xC0000000）
3. **用户空间页表**：为进程创建独立的页目录
4. **页错误处理**：实现页错误中断处理程序（ISR 14）
5. **TLB 管理**：使用 `invlpg` 指令刷新 TLB
6. **4MB 大页**：使用 PSE（Page Size Extension）支持 4MB 页

## 11. 相关硬件文档

### 11.1 控制寄存器

| 寄存器 | 作用 |
|--------|------|
| CR0 | 系统控制（PG位启用分页） |
| CR2 | 页错误线性地址 |
| CR3 | 页目录基址（PDBR） |
| CR4 | 扩展功能（PSE、PAE等） |

### 11.2 页表项标志位

| 位 | 名称 | 说明 |
|----|------|------|
| 0 | P (Present) | 页存在内存中 |
| 1 | R/W | 0=只读，1=可读写 |
| 2 | U/S | 0=特权级，1=用户级 |
| 3 | PWT | 写通（Write-Through） |
| 4 | PCD | 禁用缓存 |
| 5 | A (Accessed) | CPU设置，表示被访问过 |
| 6 | D (Dirty) | CPU设置，表示被写入过 |
| 7 | PS/PAT | 页大小/页属性表 |
| 8 | G (Global) | 全局页，TLB不刷新 |
