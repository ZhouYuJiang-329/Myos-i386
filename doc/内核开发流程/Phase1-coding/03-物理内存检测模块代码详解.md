# 物理内存检测模块代码详解

## 1. 模块概述

物理内存检测模块负责：
1. **内存检测**：通过 BIOS E820 中断获取系统物理内存布局
2. **内存管理**：基于位图（Bitmap）实现物理页帧的分配与释放

---

## 2. 核心数据结构

### 2.1 E820 内存映射条目

```c
// oskernel/kernel/mm/mem_detect.h
typedef struct {
    uint64_t base;      // 物理基地址
    uint64_t length;    // 长度
    uint32_t type;      // 类型
} __attribute__((packed)) e820_entry_t;
```

**设计说明**：
- 使用 `__attribute__((packed))` 禁止编译器填充，确保结构体大小为 20 字节
- 与 BIOS E820 返回的 ARDS（Address Range Descriptor Structure）格式完全匹配
- `type` 字段含义：1=可用, 2=保留, 3=ACPI可回收, 4=ACPI NVS, 5=不可用

### 2.2 内存映射表

```c
typedef struct {
    uint32_t count;                     // 条目数量
    e820_entry_t entries[MAX_E820_ENTRIES];  // 条目数组
} memory_map_t;
```

**内存布局**：
```
物理地址 0x1100:
  0x1100: count (4字节)
  0x1104: entry[0] (20字节)
  0x1118: entry[1] (20字节)
  ...
```

### 2.3 物理内存管理器

```c
typedef struct {
    uint32_t total_pages;       // 总页数
    uint32_t free_pages;        // 空闲页数
    uint32_t used_pages;        // 已用页数
    uint32_t *bitmap;           // 位图指针
    uint32_t bitmap_size;       // 位图大小（字节）
    uint32_t start_pfn;         // 起始物理页帧号
} pmm_t;
```

## 3. 实模式下的 E820 内存检测 (setup.asm)

### 3.1 核心代码

```nasm
; oskernel/boot/setup.asm
detect_memory_e820:
    mov     ax, 0
    mov     es, ax              ; es = 0
    mov     di, MEMORY_MAP_ADDR + 4  ; di = 缓冲区+4 (跳过count字段)
    xor     ebx, ebx            ; ebx = 0 (第一次调用)
    xor     bp, bp              ; bp = 条目计数

.e820_loop:
    mov     edx, 0x534D4150     ; 'SMAP' 签名
    mov     eax, 0xE820         ; 功能号
    mov     ecx, 20             ; ARDS 结构大小 20 字节
    int     0x15                ; 调用BIOS
    jc      .e820_failed        ; 如果CF=1，调用失败

    cmp     eax, 0x534D4150     ; 检查返回签名
    jne     .e820_failed

    ; BIOS 已经把数据写入 es:di
    add     di, cx              ; 移动到下一个条目位置
    inc     bp                  ; 条目数+1

    cmp     ebx, 0              ; 检查是否还有更多条目
    jne     .e820_loop          ; ebx!=0 继续循环

.e820_done:
    mov     ax, 0
    mov     es, ax
    mov     bx, MEMORY_MAP_ADDR
    movzx   eax, bp             ; 将16位bp扩展为32位eax
    mov     [bx], eax           ; 保存条目数量(32位)
    ret
```

### 3.2 E820 调用约定

| 寄存器 | 输入 | 输出 |
|--------|------|------|
| EAX | 0xE820 | 'SMAP' (签名) |
| EBX | 0 (首次) | 下次调用值 (0=结束) |
| ECX | 缓冲区大小 (20) | 实际写入字节数 |
| EDX | 'SMAP' (0x534D4150) | 保持不变 |
| ES:DI | 缓冲区地址 | - |
| CF | - | 0=成功, 1=失败 |

### 3.3 关键陷阱：16位实模式寻址

```nasm
; 错误写法！在16位实模式下，0x1100 会被符号扩展为 0xFFFF8000
mov     dword [0x1100], 2

; 正确写法：使用寄存器间接寻址
mov     bx, 0x1100
mov     dword [bx], 2
```

**原理**：16位模式下，直接寻址 `[imm16]` 会被符号扩展为32位。地址 >= 0x8000 时，高位补1，导致访问错误地址。

## 4. 物理内存管理器实现

### 4.1 核心宏定义

```c
// oskernel/kernel/mm/mem_detect.c
#define PAGE_SIZE 4096
#define PAGE_SHIFT 12

// 地址与页帧号互转
#define ADDR_TO_PFN(addr) ((uint32_t)(addr) >> PAGE_SHIFT)
#define PFN_TO_ADDR(pfn) ((void*)((uint32_t)(pfn) << PAGE_SHIFT))
```

### 4.2 PMM 初始化

```c
void pmm_init(void) {
    // 1. 遍历内存映射，找到最大可用地址
    uint64_t max_addr = 0;
    for (uint32_t i = 0; i < g_memory_map->count; i++) {
        e820_entry_t *entry = &g_memory_map->entries[i];
        if (entry->type == E820_USABLE) {
            uint64_t end = entry->base + entry->length;
            if (end > max_addr) max_addr = end;
        }
    }

    // 2. 从 1MB 开始管理（低内存保留给 BIOS/内核）
    pmm.start_pfn = ADDR_TO_PFN(0x100000);  // PFN 256
    uint32_t max_pfn = ADDR_TO_PFN(max_addr);
    pmm.total_pages = max_pfn - pmm.start_pfn;

    // 3. 计算位图大小（每页1bit）
    pmm.bitmap_size = (pmm.total_pages + 7) / 8;

    // 4. 位图存放在 0x20000（128KB处，内核之后）
    pmm.bitmap = (uint32_t*)0x20000;

    // 5. 清空位图（0 = 空闲）
    for (uint32_t i = 0; i < pmm.bitmap_size / 4; i++) {
        pmm.bitmap[i] = 0;
    }

    // 6. 标记已用内存（内核区域 0x1200 - 0x20000+位图大小）
    // ... 标记代码见下文
}
```

### 4.3 位图标记算法

```c
// 标记一段物理内存为已用
uint32_t kernel_start_pfn = ADDR_TO_PFN(0x1200);
uint32_t kernel_end_pfn = ADDR_TO_PFN(0x20000 + pmm.bitmap_size);

for (uint32_t pfn = kernel_start_pfn; pfn < kernel_end_pfn && pfn < max_pfn; pfn++) {
    if (pfn >= pmm.start_pfn) {
        uint32_t idx = pfn - pmm.start_pfn;     // 位图内索引
        uint32_t i = idx / 32;                   // 哪个 uint32
        uint32_t j = idx % 32;                   // 哪个 bit
        pmm.bitmap[i] |= (1 << j);               // 置1（已用）
    }
}
```

**位图布局示例**：
```
PFN 256 (0x100000) -> bitmap[0] bit 0
PFN 257 (0x101000) -> bitmap[0] bit 1
...
PFN 287 (0x11F000) -> bitmap[0] bit 31
PFN 288 (0x120000) -> bitmap[1] bit 0
```

### 4.4 页分配算法

```c
void* pmm_alloc_page(void) {
    if (pmm.free_pages == 0) return 0;

    // 遍历位图数组
    for (uint32_t i = 0; i < pmm.bitmap_size / 4; i++) {
        // 跳过全满的 uint32
        if (pmm.bitmap[i] != 0xFFFFFFFF) {
            // 在该 uint32 中找第一个0位
            for (uint32_t j = 0; j < 32; j++) {
                if (!(pmm.bitmap[i] & (1 << j))) {
                    // 找到空闲页
                    uint32_t pfn = pmm.start_pfn + i * 32 + j;
                    pmm.bitmap[i] |= (1 << j);  // 标记为已用
                    pmm.free_pages--;
                    pmm.used_pages++;
                    return PFN_TO_ADDR(pfn);     // 返回物理地址
                }
            }
        }
    }
    return 0;  // 没找到
}
```

**算法复杂度**：O(n/32)，n 为总页数。实际很快，因为跳过全满的 uint32。

### 4.5 页释放算法

```c
void pmm_free_page(void* page) {
    if (!page) return;

    uint32_t pfn = ADDR_TO_PFN((uint32_t)page);

    // 边界检查
    if (pfn < pmm.start_pfn || pfn >= pmm.start_pfn + pmm.total_pages)
        return;

    uint32_t idx = pfn - pmm.start_pfn;
    uint32_t i = idx / 32;
    uint32_t j = idx % 32;

    // 检查是否已分配（防止重复释放）
    if (!(pmm.bitmap[i] & (1 << j))) return;

    pmm.bitmap[i] &= ~(1 << j);  // 清0（空闲）
    pmm.free_pages++;
    pmm.used_pages--;
}
```

## 5. 内存布局示意图

```
物理地址空间 (以 512MB 内存为例):

0x00000000 - 0x0009FFFF:  常规内存 (640KB, Usable)
0x000A0000 - 0x000FFFFF:  保留区域 (显卡、BIOS等)
0x00100000 - 0x00101FFF:  内核代码 (head.asm + main.c)
0x00102000 - 0x0011FFFF:  内核数据/栈
0x00120000 - 0x00120FFF:  位图区域 (约4KB，管理508MB)
0x00121000 - 0x1FFFFFFF:  可用内存 (约 508MB)

PMM 管理范围:
  start_pfn = 256 (0x100000)
  total_pages = 130048 (508MB)
  bitmap @ 0x20000 (128KB)
```

## 6. 关键设计决策

### 6.1 为什么从 1MB 开始管理？

- **0-640KB**: 常规内存，但可能有 BIOS 数据、显存等混杂
- **640KB-1MB**: 保留区域（VGA显存、ROM等）
- **1MB+**: 纯净的可用内存，适合统一分配

### 6.2 为什么位图放在 0x20000？

- 内核加载在 0x1200，最大约 60KB
- 0x20000 (128KB) 在内核之后，有足够空间
- 位图大小约 4KB（管理 508MB），不会溢出

### 6.3 为什么用位图而不是链表？

| 方案 | 优点 | 缺点 |
|------|------|------|
| 位图 | O(1)访问，空间紧凑，缓存友好 | 分配需扫描 |
| 链表 | 分配快 | 空间开销大，碎片化 |

位图更适合嵌入式/内核场景。

## 7. 调试技巧

### 7.1 验证内存映射

```c
void print_memory_map(void) {
    serial_printf("Total entries: %d\n", g_memory_map->count);
    for (uint32_t i = 0; i < g_memory_map->count; i++) {
        e820_entry_t *entry = &g_memory_map->entries[i];
        serial_printf("[%d] 0x%x%08x - 0x%x%08x : %d MB\n",
            i,
            (uint32_t)(entry->base >> 32),
            (uint32_t)(entry->base),
            (uint32_t)((entry->base + entry->length) >> 32),
            (uint32_t)(entry->base + entry->length),
            (uint32_t)(entry->length / (1024 * 1024)));
    }
}
```

### 7.2 验证位图状态

```c
// 打印前几个 uint32 的位图状态
for (int i = 0; i < 4; i++) {
    serial_printf("bitmap[%d] = 0x%08x\n", i, pmm.bitmap[i]);
}
```

## 8. 扩展方向

1. **多区域管理**: 当前只管理最大连续区域，可扩展为管理多个不连续区域
2. **伙伴系统**: 用伙伴算法替代线性扫描，提高分配效率
3. **SLAB 分配器**: 在小对象频繁分配场景下使用
4. **虚拟内存**: 基于物理内存管理实现页表和虚拟地址空间
