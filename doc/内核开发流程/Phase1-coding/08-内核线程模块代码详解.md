# 内核线程模块代码详解

## 1. 核心思想

线程的本质就是：**伪造一个栈，让 CPU "以为" 它刚被中断过，通过 `ret` 指令跳转到我们指定的函数执行**。

---

## 2. 内存布局：一页 = 一个线程

```
get_kernel_pages(1) 分配的 4KB 物理页：

高地址 (页顶)
┌─────────────────────────────┐  ← self_kstack 初始位置
│                             │
│   中断栈 intr_stack         │  线程被中断时，CPU 自动保存的寄存器
│   (预留，暂不使用)          │
│                             │
├─────────────────────────────┤
│                             │
│   线程栈 thread_stack       │  我们手工布置的"假栈帧"
│   ebp,ebx,edi,esi          │
│   eip → kernel_thread      │  ← ret 跳转到这里
│   unused_retaddr            │
│   function                  │  要执行的函数地址
│   func_arg                  │  函数参数
│                             │
├─────────────────────────────┤
│                             │
│   task_struct (PCB)         │  线程管理信息
│   name, status, priority    │
│   stack_magic               │  栈溢出检测魔数
│                             │
└─────────────────────────────┘  ← 页起始地址
低地址
```

**关键设计**：PCB 在页底部，栈从页顶部向下生长。如果栈溢出到 PCB 区域，`stack_magic` 会被破坏，可以检测到。

---

## 3. 核心数据结构

### 3.1 task_struct（PCB，进程控制块）

```c
// oskernel/kernel/thread/thread.h
struct task_struct {
   uint32_t* self_kstack;       // 线程栈顶指针
   enum task_status status;     // 线程状态
   uint8_t priority;            // 线程优先级
   char name[16];               // 线程名称
   uint32_t stack_magic;        // 栈溢出检测魔数
};
```

**字段说明**：

| 字段 | 说明 |
|------|------|
| `self_kstack` | 指向线程栈顶，切换线程时 ESP 会指向这里 |
| `status` | TASK_RUNNING / TASK_READY / TASK_BLOCKED 等 |
| `priority` | 优先级，数值越大优先级越高 |
| `name` | 线程名称，用于调试 |
| `stack_magic` | 固定值 0x19870916，用于检测栈溢出 |

### 3.2 intr_stack（中断栈）

```c
struct intr_stack {
    uint32_t vec_no;        // 中断号
    uint32_t edi;           // 通用寄存器
    uint32_t esi;
    uint32_t ebp;
    uint32_t esp_dummy;
    uint32_t ebx;
    uint32_t edx;
    uint32_t ecx;
    uint32_t eax;
    uint32_t gs;            // 段寄存器
    uint32_t fs;
    uint32_t es;
    uint32_t ds;
    uint32_t err_code;      // 错误码
    void (*eip) (void);     // 返回地址
    uint32_t cs;
    uint32_t eflags;
    void* esp;
    uint32_t ss;
};
```

**用途**：线程被中断时，CPU 会按照这个结构压入寄存器。当前模块预留但暂未使用。

### 3.3 thread_stack（线程栈）

```c
struct thread_stack {
   uint32_t ebp;            // 保存的寄存器
   uint32_t ebx;
   uint32_t edi;
   uint32_t esi;
   void (*eip) (thread_func* func, void* func_arg);  // kernel_thread 地址
   void (*unused_retaddr);                             // 返回地址（不用）
   thread_func* function;                              // 要执行的函数
   void* func_arg;                                     // 函数参数
};
```

**这是最关键的数据结构**——它模拟了一个函数调用栈帧，使得 `ret` 指令能跳转到 `kernel_thread` 执行。

## 4. 执行流程：四步启动线程

### 第 1 步：分配内存（thread_start）

```c
struct task_struct* thread = get_kernel_pages(1);  // 分配 4KB
```

得到一块 4KB 的物理页，起始地址就是 PCB 的起始地址。

### 第 2 步：初始化 PCB（init_thread）

```c
void init_thread(struct task_struct* pthread, char* name, int prio) {
   memset(pthread, 0, sizeof(*pthread));       // 清零
   strcpy(pthread->name, name);                // 设置线程名
   pthread->status = TASK_RUNNING;             // 状态：运行中
   pthread->priority = prio;                   // 优先级

   // 栈顶 = PCB地址 + 4KB（页的最高地址）
   pthread->self_kstack = (uint32_t*)((uint32_t)pthread + PG_SIZE);

   pthread->stack_magic = 0x19870916;          // 栈溢出检测魔数
}
```

**此时 self_kstack 指向页顶**：
```
页顶 ──→ 0x21000 (假设 PCB 在 0x20000)
```

### 第 3 步：伪造栈帧（thread_create）

**这是最核心的部分**——在栈上布置数据，模拟一个"被中断后的栈帧"：

```c
void thread_create(struct task_struct* pthread, thread_func function, void* func_arg) {
   // 1. 向下预留中断栈空间（-72 字节）
   pthread->self_kstack = (uint32_t*)((int)(pthread->self_kstack) - sizeof(struct intr_stack));

   // 2. 向下预留线程栈空间（-48 字节）
   pthread->self_kstack = (uint32_t*)((int)(pthread->self_kstack) - sizeof(struct thread_stack));

   struct thread_stack* kthread_stack = (struct thread_stack*)pthread->self_kstack;

   // 3. 在线程栈中填入数据
   kthread_stack->eip = kernel_thread;   // ret 时跳转到这里
   kthread_stack->function = function;    // 传给 kernel_thread 的参数
   kthread_stack->func_arg = func_arg;    // 传给 kernel_thread 的参数
   kthread_stack->ebp = 0;
   kthread_stack->ebx = 0;
   kthread_stack->edi = 0;
   kthread_stack->esi = 0;
}
```

**布置后的栈**（self_kstack 指向的位置）：

```
self_kstack ──→ ┌─────────────────────────┐
                │ ebp = 0                 │  ← pop ebp
                │ ebx = 0                 │  ← pop ebx
                │ edi = 0                 │  ← pop edi
                │ esi = 0                 │  ← pop esi
                │ eip = kernel_thread     │  ← ret 跳转！
                │ unused_retaddr          │  ← kernel_thread 的"返回地址"（不用管）
                │ function = func         │  ← kernel_thread 的参数1
                │ func_arg = arg          │  ← kernel_thread 的参数2
                ├─────────────────────────┤
                │ intr_stack (预留)       │
                ├─────────────────────────┤
                │ task_struct (PCB)       │
                └─────────────────────────┘
```

### 第 4 步：切换栈并执行（thread_start）

```c
struct task_struct* thread_start(char* name, int prio, thread_func function, void* func_arg) {
   struct task_struct* thread = get_kernel_pages(1);   // 分配 PCB
   init_thread(thread, name, prio);                    // 初始化 PCB
   thread_create(thread, function, func_arg);          // 伪造栈帧

   // 切换到新线程的栈，开始执行
   asm volatile (
       "movl %0, %%esp;   "  // 1. ESP = self_kstack（指向伪造栈顶）
       "pop %%ebp;         "  // 2. pop ebp (ebp = 0)
       "pop %%ebx;         "  // 3. pop ebx (ebx = 0)
       "pop %%edi;         "  // 4. pop edi (edi = 0)
       "pop %%esi;         "  // 5. pop esi (esi = 0)
       "ret                "  // 6. ret → 跳转到 kernel_thread！
       : : "g" (thread->self_kstack) : "memory"
   );
   return thread;
}
```

**执行 `ret` 时**：
- CPU 从栈顶弹出 `eip` 的值（即 `kernel_thread` 的地址）
- 跳转到 `kernel_thread` 执行
- 同时栈上还有 `function` 和 `func_arg`，它们恰好是 `kernel_thread` 的参数

---

## 5. kernel_thread：线程启动器

```c
static void kernel_thread(thread_func* function, void* func_arg) {
    function(func_arg);  // 调用用户传入的函数
}
```

### 为什么需要这个中间层？

如果直接把 `ret` 跳转到用户的 `function`，有一个问题：`function` 的参数怎么传？

通过 `kernel_thread` 作为中间层，我们可以利用 C 调用约定（cdecl）：
- `function` 和 `func_arg` 在栈上，恰好是 `kernel_thread` 的两个参数
- `kernel_thread` 再调用 `function(func_arg)`，参数传递由 C 编译器自动处理

## 6. 完整执行流程图

```
thread_start("k_thread_a", 31, k_thread_a, "hello")
    │
    ├── get_kernel_pages(1)          // 分配 4KB 页
    │
    ├── init_thread()                // 初始化 PCB
    │     self_kstack = 页顶
    │
    ├── thread_create()              // 伪造栈帧
    │     self_kstack → [ebp|ebx|edi|esi|kernel_thread|ret|function|arg]
    │
    └── 内联汇编
          mov esp, self_kstack       // ESP 指向伪造栈
          pop ebp                    // ebp = 0
          pop ebx                    // ebx = 0
          pop edi                    // edi = 0
          pop esi                    // esi = 0
          ret                        // eip = kernel_thread → 跳转！
              │
              ▼
          kernel_thread(function, func_arg)
              │
              └── function(func_arg)   // 执行 k_thread_a("hello")
                    │
                    └── while(1) { vga_puts("hello"); }
```

## 7. 关键点总结

| 概念 | 说明 |
|------|------|
| **线程 = 页** | 每个线程占一个 4KB 页，PCB 在底部，栈在顶部 |
| **伪造栈帧** | 手工在栈上布置寄存器值和函数地址，模拟被中断的状态 |
| **ret 启动** | 通过 `ret` 指令从伪造栈中弹出地址，跳转到目标函数 |
| **kernel_thread** | 启动器，解决参数传递问题 |
| **self_kstack** | 指向当前线程的栈顶，切换线程时修改 ESP 即可 |

**本质**：线程切换就是 **切换 ESP 指针**。每个线程有自己的栈，栈上保存了完整的执行上下文。切换时只需要把 ESP 指向新线程的栈，然后 `pop` + `ret` 就能恢复执行。

## 8. 测试代码

```c
// main.c
void k_thread_a(void *arg) {
    char *message = (char*)arg;
    while(1) {
        vga_puts(message);
    }
}

// 在 kernel_main 中调用
thread_start("k_thread_a", 31, k_thread_a, "thread_a");
```

**预期效果**：线程启动后，会在 VGA 屏幕上持续输出 "thread_a"。
