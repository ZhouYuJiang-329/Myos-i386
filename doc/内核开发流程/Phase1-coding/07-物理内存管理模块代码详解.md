# 物理内存管理模块代码详解

## 1. 模块概述

物理内存管理模块负责：
1. **内存池初始化**：根据 E820 内存映射表，建立内核/用户物理内存池
2. **物理页分配**：基于位图的页帧分配器，管理物理页的分配与释放
3. **虚拟地址分配**：管理内核堆区的虚拟地址空间
4. **页表映射**：建立虚拟地址到物理地址的映射关系
5. **内存分配接口**：提供 `get_kernel_pages()` 等高级分配函数

---

## 2. 核心数据结构

### 2.1 物理内存池结构

```c
// oskernel/kernel/mm/memory.h
struct pool {
   struct bitmap pool_bitmap;   // 位图，每个 bit 管理一个物理页
   uint32_t phy_addr_start;     // 本池管理的物理内存起始地址
   uint32_t pool_size;          // 本池的字节容量
};
```

**设计思想**：
- 系统维护两个物理内存池实例：`kernel_pool`（内核专用）和 `user_pool`（用户进程专用）
- 内存池隔离确保用户进程不会耗尽内核所需的内存
- 每个物理页在位图中占 1 bit：0 = 空闲，1 = 已分配

**内存布局**：
```
kernel_pool:  物理 0x200000 ~ 0x100BF000  (~255MB)
user_pool:    物理 0x100BF000 ~ 0x1FFE0000 (~255MB)
```

### 2.2 虚拟地址池结构

```c
struct virtual_addr {
   struct bitmap vaddr_bitmap;  // 位图，管理虚拟页的分配状态
   uint32_t vaddr_start;        // 虚拟地址起始地址 (0xC0100000)
};
```

**设计思想**：
- 只有一个实例 `kernel_vaddr`，管理内核堆区的虚拟地址
- 虚拟地址起始于 `K_HEAP_START = 0xC0100000`
- 位图大小与 `kernel_pool` 相同（虚拟页数 = 物理页数）

### 2.3 内存池标志枚举

```c
enum pool_flags {
   PF_KERNEL = 1,    // 内核内存池
   PF_USER = 2       // 用户内存池
};
```

**用途**：在 `malloc_page()` 中选择从哪个物理内存池分配。

### 2.4 页表属性常量

```c
#define PG_P_1    1    // 页存在位 = 1
#define PG_P_0    0    // 页存在位 = 0
#define PG_RW_R   0    // 只读
#define PG_RW_W   2    // 可读写
#define PG_US_S   0    // 系统级（仅 Ring 0 可访问）
#define PG_US_U   4    // 用户级（Ring 3 可访问）
```

**页目录项/页表项格式**：
```
Bit:  31-12        11-9    8   7   6   5   4   3   2   1   0
    +------------+-----+---+---+---+---+---+---+---+---+---+
    | 物理页地址  | AVL | G | D | A | PCD|PWT| US| RW| P |
    +------------+-----+---+---+---+---+---+---+---+---+---+

P   = 存在位（1=页在内存中）
RW  = 读写位（0=只读, 1=可读写）
US  = 用户/系统位（0=系统级, 1=用户级）
```

## 3. 内存池初始化详解

### 3.1 初始化入口

```c
// oskernel/kernel/mm/memory.c
void mem_init() {
   serial_putline("mem_init start");
   uint32_t mem_bytes_total = get_total_memory_bytes();  // 从 E820 表获取总可用内存
   serial_printf("Total usable memory: %d MB\n", mem_bytes_total / (1024 * 1024));
   mem_pool_init(mem_bytes_total);   // 初始化内存池
   serial_putline("mem_init done");
}
```

**调用链**：
```
mem_init()
  → get_total_memory_bytes()    // 遍历 E820 表累加可用内存
  → mem_pool_init(mem_bytes)    // 初始化三个池（内核物理、用户物理、内核虚拟）
```

### 3.2 内存池初始化核心逻辑

```c
static void mem_pool_init(uint32_t all_mem) {
   // 1. 计算已用内存
   uint32_t page_table_size = PG_SIZE * 256;     // 256 个页表 = 1MB
   uint32_t used_mem = page_table_size + 0x100000; // 已用 = 1MB 内存 + 1MB 页表 = 2MB

   // 2. 计算空闲内存并平分
   uint32_t free_mem = all_mem - used_mem;
   uint32_t all_free_pages = free_mem / PG_SIZE;       // 转换为页数
   uint32_t kernel_free_pages = all_free_pages / 2;    // 内核占一半
   uint32_t user_free_pages = all_free_pages - kernel_free_pages;  // 用户占另一半

   // 3. 计算位图大小（每页占 1 bit）
   uint32_t kbm_length = kernel_free_pages / 8;   // 内核位图字节数
   uint32_t ubm_length = user_free_pages / 8;     // 用户位图字节数

   // 4. 计算池的起始物理地址
   uint32_t kp_start = used_mem;                           // 内核池从 2MB 开始
   uint32_t up_start = kp_start + kernel_free_pages * PG_SIZE;  // 用户池紧跟其后
```

**计算示例（511MB 系统）**：
```
all_mem       = 511 MB = 535,877,632 bytes
used_mem      = 2 MB   = 2,097,152 bytes
free_mem      = 509 MB = 533,780,480 bytes
all_free_pages = 130,320 页
kernel_pages  = 65,160 页 (~254MB)
user_pages    = 65,160 页 (~254MB)
kbm_length    = 8,145 字节 (~8KB)
kp_start      = 0x200000 (2MB)
up_start      = 0x100BF000 (~257MB)
```

### 3.3 位图放置策略

```c
   // 5. 位图放置在低 1MB 的空闲区域
   //    内核池位图在 0x9A000，用户池位图紧跟其后
   kernel_pool.pool_bitmap.bits = (void*)MEM_BITMAP_BASE;               // 0xc009a000 → 物理 0x9a000
   user_pool.pool_bitmap.bits = (void*)(MEM_BITMAP_BASE + kbm_length); // 物理 0x9a000 + 8KB

   // 6. 虚拟地址位图在用户池位图之后
   kernel_vaddr.vaddr_bitmap.bits = (void*)(MEM_BITMAP_BASE + kbm_length + ubm_length);
   kernel_vaddr.vaddr_start = K_HEAP_START;  // 0xC0100000

   // 7. 清零所有位图
   bitmap_init(&kernel_pool.pool_bitmap);
   bitmap_init(&user_pool.pool_bitmap);
   bitmap_init(&kernel_vaddr.vaddr_bitmap);
}
```

**低 1MB 位图布局**：
```
0x9A000 ┌──────────────────────┐
        │ 内核池位图 (~8KB)     │
0x9C000 ├──────────────────────┤
        │ 用户池位图 (~8KB)     │
0x9E000 ├──────────────────────┤
        │ 虚拟地址位图 (~8KB)   │
0x9F000 ├──────────────────────┤
        │ 内核栈 (4KB)         │
0xA0000 └──────────────────────┘
```

**为什么放在低 1MB？**
- head.asm 建立的页表只映射了低 1MB（恒等映射）
- 虚拟地址 0x9A000 映射到物理地址 0x9A000，可直接访问
- 高于 1MB 的地址在当前页表中未映射，访问会触发 page_fault

## 4. 物理页分配详解

### 4.1 palloc() — 分配一个物理页

```c
static void* palloc(struct pool* m_pool) {
    // 1. 在位图中扫描一个空闲位
    int bit_idx = bitmap_scan(&m_pool->pool_bitmap, 1);

    // 2. 没有空闲页
    if (bit_idx == -1) {
        return NULL;
    }

    // 3. 标记为已分配（置1）
    bitmap_set(&m_pool->pool_bitmap, bit_idx, 1);

    // 4. 计算物理地址
    uint32_t page_phyaddr = (bit_idx * PG_SIZE) + m_pool->phy_addr_start;
    return (void*)page_phyaddr;
}
```

**地址计算原理**：
```
位图中第 bit_idx 位 = 1  →  对应第 bit_idx 个物理页
物理地址 = bit_idx × 4096 + 池起始地址
```

**示例**：
```
kernel_pool.phy_addr_start = 0x200000
bit_idx = 0  →  物理地址 = 0×4096 + 0x200000 = 0x200000
bit_idx = 1  →  物理地址 = 1×4096 + 0x200000 = 0x201000
bit_idx = 100 → 物理地址 = 100×4096 + 0x200000 = 0x264000
```

### 4.2 palloc_release() — 释放物理页（待完善）

```c
static void palloc_release(struct pool* m_pool, uint32_t page_phyaddr) {
    uint32_t bit_idx = (page_phyaddr - m_pool->phy_addr_start) / PG_SIZE;
    bitmap_set(&m_pool->pool_bitmap, bit_idx, 0);  // 清除位图
}
```

**逆运算**：从物理地址反推位图索引。

## 5. 虚拟地址分配详解

### 5.1 vaddr_get() — 分配连续虚拟页

```c
static void* vaddr_get(enum pool_flags pf, uint32_t pg_cnt) {
    int vaddr_start = 0, bit_idx_start = -1;
    uint32_t cnt = 0;

    if (pf == PF_KERNEL) {
        // 1. 在虚拟地址位图中扫描 pg_cnt 个连续空闲位
        bit_idx_start = bitmap_scan(&kernel_vaddr.vaddr_bitmap, pg_cnt);

        // 2. 分配失败
        if (bit_idx_start == -1) {
            return NULL;
        }

        // 3. 逐个标记为已分配
        while (cnt < pg_cnt) {
            bitmap_set(&kernel_vaddr.vaddr_bitmap, bit_idx_start + cnt++, 1);
        }

        // 4. 计算虚拟地址
        vaddr_start = kernel_vaddr.vaddr_start + bit_idx_start * PG_SIZE;
    }
    // 用户内存池预留，待实现

    return (void*)vaddr_start;
}
```

**与 palloc 的区别**：
| | palloc | vaddr_get |
|---|---|---|
| 分配对象 | 物理页 | 虚拟页 |
| 位图 | kernel_pool / user_pool | kernel_vaddr |
| 返回值 | 物理地址 | 虚拟地址 |
| 连续性 | 不保证 | 保证连续 |

## 6. 页表映射详解

### 6.1 递归页目录原理

x86 页表使用两级结构：页目录（Page Directory）→ 页表（Page Table）→ 物理页。

**递归映射技巧**：将页目录的第 1023 项指向页目录自身，使得可以通过虚拟地址访问页表结构本身。

```
页目录第 1023 项 → 指向页目录自身

访问 PDE：
  虚拟地址 = 0xFFFFF000 + PDE索引 × 4
  含义：通过第 1023 项进入页目录，再用 PDE 索引定位具体项

访问 PTE：
  虚拟地址 = 0xFFC00000 + PDE索引 × 1024 × 4 + PTE索引 × 4
  含义：通过第 1023 项进入页目录 → 找到 PDE 指向的页表 → 用 PTE 索引定位
```

### 6.2 pde_ptr() — 获取页目录项指针

```c
#define PDE_IDX(addr) ((addr & 0xffc00000) >> 22)

uint32_t* pde_ptr(uint32_t vaddr) {
    // 0xFFFFF000 = 递归映射到页目录自身
    // PDE_IDX(vaddr) × 4 = 页目录中第几个项（每项 4 字节）
    uint32_t* pde = (uint32_t*)(0xFFFFF000 + PDE_IDX(vaddr) * 4);
    return pde;
}
```

**地址分解**：
```
虚拟地址 vaddr:  0x12345678
                 ┌─────────┬──────────┬──────────┐
  二进制:        │ 00 0001 │ 0011 0100 │ 0101 0110 │ 0111 1000 │
                 │ PDE(10位)│ PTE(10位) │ Offset(12位)│
                 └─────────┴──────────┴──────────┘

PDE_IDX = (0x12345678 & 0xFFC00000) >> 22 = 0x04
PDE 地址 = 0xFFFFF000 + 0x04 × 4 = 0xFFFFF010
```

### 6.3 pte_ptr() — 获取页表项指针

```c
#define PTE_IDX(addr) ((addr & 0x003ff000) >> 12)

uint32_t* pte_ptr(uint32_t vaddr) {
    // 0xFFC00000 = 递归映射到页表区域
    // (vaddr & 0xFFC00000) >> 10 = PDE索引 × 1024 × 4（跳到对应页表）
    // PTE_IDX(vaddr) × 4 = 页表内第几个项
    uint32_t* pte = (uint32_t*)(0xFFC00000
                                + ((vaddr & 0xFFC00000) >> 10)
                                + PTE_IDX(vaddr) * 4);
    return pte;
}
```

**计算过程**：
```
vaddr = 0x12345678

(vaddr & 0xFFC00000) >> 10 = 0x12000000 >> 10 = 0x48000
PTE_IDX(vaddr) = (0x12345678 & 0x003FF000) >> 12 = 0x345

PTE 地址 = 0xFFC00000 + 0x48000 + 0x345 × 4
         = 0xFFC00000 + 0x48000 + 0xD14
         = 0xFFC48D14
```

### 6.4 page_table_add() — 建立映射

```c
static void page_table_add(void* _vaddr, void* _page_phyaddr) {
    uint32_t vaddr = (uint32_t)_vaddr;
    uint32_t page_phyaddr = (uint32_t)_page_phyaddr;
    uint32_t* pde = pde_ptr(vaddr);    // 获取页目录项
    uint32_t* pte = pte_ptr(vaddr);    // 获取页表项

    // 情况1：页目录项已存在（P=1）
    if (*pde & 0x00000001) {
        // 直接设置页表项
        *pte = (page_phyaddr | PG_US_U | PG_RW_W | PG_P_1);
    }
    // 情况2：页目录项不存在（P=0）
    else {
        // 2.1 从内核池分配一个物理页作为新页表
        uint32_t pde_phyaddr = (uint32_t)palloc(&kernel_pool);

        // 2.2 设置页目录项，指向新页表
        *pde = (pde_phyaddr | PG_US_U | PG_RW_W | PG_P_1);

        // 2.3 清零新页表（避免旧数据干扰）
        memset((void*)((int)pte & 0xfffff000), 0, PG_SIZE);

        // 2.4 设置页表项
        *pte = (page_phyaddr | PG_US_U | PG_RW_W | PG_P_1);
    }
}
```

**流程图**：
```
page_table_add(vaddr, phyaddr)
    │
    ├── PDE 存在？
    │   ├── YES → 直接写入 PTE
    │   └── NO  → 分配新页表页 → 清零 → 写入 PDE → 写入 PTE
```

**⚠️ 关键注意点**：
- 必须先写 PDE 再访问 `*pte`，否则会访问到未映射的内存导致 page_fault
- 新页表页必须清零，否则残留数据会被当作页表项，导致内存访问异常

## 7. 高级分配接口详解

### 7.1 malloc_page() — 分配内存（三步合成）

```c
void* malloc_page(enum pool_flags pf, uint32_t pg_cnt) {
    // 步骤1：在虚拟地址池中分配连续虚拟页
    void* vaddr_start = vaddr_get(pf, pg_cnt);
    if (vaddr_start == NULL) {
        return NULL;
    }

    uint32_t vaddr = (uint32_t)vaddr_start, cnt = pg_cnt;
    struct pool* mem_pool = pf & PF_KERNEL ? &kernel_pool : &user_pool;

    // 步骤2：逐个分配物理页并建立映射
    while (cnt-- > 0) {
        void* page_phyaddr = palloc(mem_pool);
        if (page_phyaddr == NULL) {
            // 失败回滚（待完善）
            return NULL;
        }
        page_table_add((void*)vaddr, page_phyaddr);  // 步骤3：建立映射
        vaddr += PG_SIZE;
    }
    return vaddr_start;
}
```

**三步合成原理**：
```
┌─────────────────────────────────────────────────────┐
│  malloc_page(PF_KERNEL, 3)                          │
│                                                     │
│  1. vaddr_get()                                     │
│     虚拟位图: [0][0][0][1][1][1][0][0]...           │
│     返回: 0xC0100000 (3个连续虚拟页)                │
│                                                     │
│  2. palloc() × 3                                    │
│     物理位图: [1][0][1][0][1][0][0][0]...           │
│     分配: 0x200000, 0x203000, 0x208000 (不要求连续)  │
│                                                     │
│  3. page_table_add() × 3                            │
│     页表:                                             │
│     0xC0100000 → 0x200000                           │
│     0xC0101000 → 0x203000                           │
│     0xC0102000 → 0x208000                           │
└─────────────────────────────────────────────────────┘
```

### 7.2 get_kernel_pages() — 内核内存分配

```c
void* get_kernel_pages(uint32_t pg_cnt) {
    void* vaddr = malloc_page(PF_KERNEL, pg_cnt);
    if (vaddr != NULL) {
        memset(vaddr, 0, pg_cnt * PG_SIZE);  // 清零
    }
    return vaddr;
}
```

**与 malloc_page 的区别**：
- 只从内核池分配（`PF_KERNEL`）
- 分配后自动清零（`memset`）
- 是对外暴露的公共接口

## 8. 完整调用链

```
用户调用
  │
  ▼
get_kernel_pages(pg_cnt)          // 对外接口
  │
  ├── memset(vaddr, 0, size)      // 清零
  │
  └── malloc_page(PF_KERNEL, pg_cnt)
        │
        ├── vaddr_get()           // 虚拟地址分配
        │     └── bitmap_scan()   // 扫描虚拟位图
        │
        ├── palloc() × N          // 物理页分配
        │     └── bitmap_scan()   // 扫描物理位图
        │
        └── page_table_add() × N  // 页表映射
              ├── pde_ptr()       // 获取页目录项
              ├── pte_ptr()       // 获取页表项
              ├── palloc()        // 新页表页（如果需要）
              └── memset()        // 清零新页表页
```

## 9. 已知问题

### 9.1 缺少回滚机制

`malloc_page()` 分配多个页时，如果中途 `palloc` 失败，已分配的虚拟页和物理页不会被回收。

**影响**：
- 虚拟地址位图中已标记的位不会被清除 → 虚拟地址泄漏
- 物理页已分配但未映射 → 物理页泄漏

**修复方案**：失败时遍历已分配的页，清除位图和页表项。

### 9.2 内核堆区页表未扩展

`K_HEAP_START = 0xC0100000` 目前在页表中没有映射。`get_kernel_pages()` 返回的虚拟地址访问时会触发 page_fault。

**待做**：扩展 head.asm 的页表，映射 0xC0100000+ 的虚拟地址到物理内存。

### 9.3 memset 在 page_table_add 中的参数

```c
memset((void*)((int)pte & 0xfffff000), 0, PG_SIZE);
```

`pte` 是通过递归映射得到的虚拟地址，`(int)pte & 0xfffff000` 取得页表页的起始地址。这里 memset 清零的是新分配的页表页，不是 PDE 本身。逻辑正确，但 `(int)` 强制转换在 64 位系统上会出问题（当前 32 位系统无此问题）。
