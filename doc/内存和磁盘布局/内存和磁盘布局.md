### 关键内存地址常量

| 常量名 | 地址值 | 定义位置 | 用途 |
|--------|--------|----------|------|
| `BOOT_MAIN_ADDR` | 0x500 | boot.asm | setup.bin 加载目标地址 |
| `MEMORY_MAP_ADDR` | 0x1100 | setup.asm | E820 内存检测结果存放 |
| `KERNEL_ADDR` | 0x1200 | setup.asm | kernel.bin 加载目标地址 |
| `CODE_SEG` | 0x08 | setup.asm | GDT 代码段选择子 |
| `DATA_SEG` | 0x10 | setup.asm | GDT 数据段选择子 |
| ESP (栈顶) | 0x90000 | setup.asm | 保护模式栈顶指针 |

### GDT 表位置

GDT 表定义在 setup.asm 中，随 setup.bin 一起加载到内存：

```
物理地址 = 0x500 + (gdt_start 在 setup.bin 中的偏移)

GDT 结构（24字节）：
├─ 0x00-0x07: 空描述符（8字节）
├─ 0x08-0x0F: 代码段描述符（8字节）← 索引 1，选择子 0x08
├─ 0x10-0x17: 数据段描述符（8字节）← 索引 2，选择子 0x10
└─ gdt_descriptor（6字节）: 界限(2B) + 基址(4B)
```

## 二、硬盘磁盘布局

### 磁盘扇区分配（LBA 模式）

```
┌─────────────────────────────────────────────────────────────────┐
│  LBA 扇区号  │  数量    │  内容          │  加载到内存   │  加载者  │
├─────────────────────────────────────────────────────────────────┤
│  0           │  1 扇区  │  boot.bin      │  0x7C00      │  BIOS   │
│  1-2         │  2 扇区  │  setup.bin     │  0x500       │  boot   │
│  3-62        │  60 扇区 │  kernel.bin    │  0x1200      │  setup  │
│  63+         │  空闲    │  用户数据      │  -           │  -      │
└─────────────────────────────────────────────────────────────────┘
```

### 磁盘镜像生成过程

```bash
# 1. 创建 32MB 硬盘镜像
bximage -q -hd=32 -func=create -sectsize=512 -imgmode=flat hd.img

# 2. 写入 boot.bin 到第 0 扇区
dd if=boot.bin of=hd.img bs=512 seek=0 count=1 conv=notrunc

# 3. 写入 setup.bin 到第 1-2 扇区
dd if=setup.bin of=hd.img bs=512 seek=1 count=2 conv=notrunc

# 4. 写入 kernel.bin 到第 3-62 扇区
dd if=kernel.bin of=hd.img bs=512 seek=3 count=60 conv=notrunc
```

## 三、启动流程与内存变化

### Stage 1: BIOS 启动

```
1. 上电，BIOS 自检
2. BIOS 从硬盘第 0 扇区读取 512 字节到内存 0x7C00
3. BIOS 跳转到 0x7C00 执行 boot.bin
```

### Stage 2: boot.bin 执行（实模式）

```
1. 设置屏幕模式为文本模式
2. 使用 LBA 模式从硬盘读取 setup.bin（扇区 1-2，共 2 扇区）
3. 加载到内存 0x500
4. 打印 "jmp to setup"
5. 跳转到 0x500 执行 setup.bin
```

### Stage 3: setup.bin 执行（实模式 → 保护模式）

```
1. 初始化段寄存器（DS, ES, FS, GS, SS = 0）
2. 打印 "hello setup!"
3. 【Step 1】调用 detect_memory_e820 检测物理内存
   - 使用 INT 0x15, AX=0xE820 获取内存映射
   - 结果存放到 0x1100（MEMORY_MAP_ADDR）
4. 【Step 2】禁用中断（cli）
5. 【Step 3】启用 A20 地址线
6. 【Step 4】加载 GDT 并进入保护模式
   - lgdt [gdt_descriptor]
   - 设置 CR0.PE = 1
   - 远跳转到 CODE_SEG:protected_mode_start
```

### Stage 4: 保护模式代码执行

```
1. 初始化保护模式段寄存器（DS, ES, FS, GS, SS = DATA_SEG = 0x10）
2. 设置栈顶 ESP = 0x90000
3. 从硬盘读取 kernel.bin（扇区 3-62，共 60 扇区）
4. 加载到内存 0x1200（KERNEL_ADDR）
5. 远跳转到 CODE_SEG:KERNEL_ADDR（0x08:0x1200）
6. 开始执行内核代码
```

### Stage 5: kernel.bin 执行（保护模式）

```
1. _start (0x1200) 入口
2. call kernel_main
3. kernel_main 执行内核初始化
   - serial_init()          初始化串口
   - print_memory_map()     打印内存映射
   - pmm_init()             初始化物理内存管理
   - ... 其他初始化
4. 进入内核主循环
```

│  0x00000000 - 0x0009FFFF  │  低端内存（640KB）        │  可用        │

## 五、编译和链接参数

### 对象文件编译

```bash
# boot/setup - 纯二进制（实模式）
nasm -f bin boot.asm -o boot.bin      # 512字节，ORG 0x7C00
nasm -f bin setup.asm -o setup.bin    # 1024字节，ORG 0x500

# 内核 - ELF32 格式（保护模式）
nasm -f elf32 head.asm -o head.o      # 生成 ELF32 对象文件
gcc -m32 -ffreestanding -fno-pic -fno-stack-protector -c main.c -o main.o
gcc -m32 -ffreestanding -fno-pic -fno-stack-protector -c serial.c -o serial.o
gcc -m32 -ffreestanding -fno-pic -fno-stack-protector -c mem_detect.c -o mem_detect.o
```

### 内核链接

```bash
ld -m elf_i386 -Ttext 0x1200 -o kernel.bin head.o main.o serial.o mem_detect.o
```

参数说明：
- `-m elf_i386`: 32位 x86 链接模式
- `-Ttext 0x1200`: 代码段起始地址为 0x1200
- 输出 kernel.bin（ELF 可执行文件，但 setup 按纯二进制加载）

## 六、重要说明

### 1. 为什么 kernel.bin 是 ELF 格式但直接加载？

setup.asm 目前直接跳转到 0x1200 执行，假设 kernel.bin 是纯二进制。但实际上 kernel.bin 是 ELF 格式，包含 ELF 头（52字节）。

**当前情况**：
- ELF 头在 0x1200-0x1233
- 实际代码（_start）在 0x1234 左右
- 直接跳转可能导致执行 ELF 头作为代码（错误！）

**建议修复**：
setup.asm 应该解析 ELF 头，读取入口点地址，再跳转。或者使用 `--oformat binary` 生成纯二进制内核。

### 2. 内存映射表格式（E820）

存放在 0x1100 处，格式如下：

```c
struct memory_map {
    uint32_t entry_count;           // 0x1100: 条目数量
    struct e820_entry {
        uint64_t base;              // 基地址（8字节）
        uint64_t length;            // 长度（8字节）
        uint32_t type;              // 类型（4字节）
        uint32_t acpi;              // ACPI 扩展（4字节）
    } entries[];                    // 0x1104 开始
};
```

类型值：
- 1: E820_USABLE（可用内存）
- 2: E820_RESERVED（保留）
- 3: E820_ACPI_RECLAIM（ACPI 可回收）
- 4: E820_ACPI_NVS（ACPI NVS）
- 5: E820_BAD（坏内存）

### 3. GDT 段描述符

| 选择子 | 索引 | 基址 | 界限 | 属性 |
|--------|------|------|------|------|
| 0x00 | 0 | - | - | 空描述符 |
| 0x08 | 1 | 0x00000000 | 0xFFFFF (4GB) | 代码段，可执行/可读，DPL=0 |
| 0x10 | 2 | 0x00000000 | 0xFFFFF (4GB) | 数据段，可读写，DPL=0 |

所有段基址为 0，界限为 4GB，采用平坦内存模型。
